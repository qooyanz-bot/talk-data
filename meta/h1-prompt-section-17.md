## 17. 正本（Canonical Record）【正式採用 2026-09-05】

### 17.1 正本の場所
正本リポジトリは次で固定する。

`https://github.com/qooyanz-bot/talk-data`

会話・Memory・一時メモは補助。未反映の新しいK決定は、反映前でもK発言が優先し、速やかに正本へ書く。反映後は正本を参照する。

### 17.2 役割
- K = 正本の最終承認者
- AI = Recorder / Verifier / 草案作成。単独で最終正本を確定しない
- チャット = 作業場。自動的には正本にならない

### 17.3 置いてよいもの / 置いてはいけないもの
置いてよい: Future Conceptドラフトと版、Address・失敗条件・閾値・ゲート、用語・境界・未決リスト、changelog、Kが承認した決定・却下・保留、検証可能な根拠リンク。
置いてはいけない: 秘密、未観測を確定事実扱い、旧解釈の固定、AI単独のFC最終版、使い捨て試行前提の設計を正とすること。

### 17.4 フォルダ対応
`future-concept/` / `gates/` / `address/` / `meta/` / `changelog/` / `README.md`
新カテゴリは README と changelog に理由を書いてから追加。

### 17.5 追加・更新の手順（必須）
1. 提案 2. 草案 3. Hard Reject（E系）と B5 の短点検 4. K承認 5. commit 6. changelog 7. 版更新
K承認なしの AI 単独 push は禁止。正本に書いた委任範囲のみ例外。

### 17.6 更新の種類
追記 / 訂正 / 改訂 / 廃止（いきなり削除しない）。改訂は必ず版上げ。

### 17.7 優先順位（衝突時）
1. Kの最新の明示決定（会話）
2. talk-data 上の現行正本
3. エージェント Memory
4. 古い会話の要約・印象
1 と 2 が食い違うときは 2 を 1 に合わせて更新する。

### 17.8 会話からの昇格ルール
正本候補: 繰り返し参照される定義・ルール・表、ゲートに効く、Kが残す意図。
正本にしない: たとえ話、未消化の質問、再現手順のない一回きり試算、トーン説明そのもの。

### 17.9 統一プロンプトとの関係
§17は全会話で有効。§17自体の変更も同じ手続き＋プロンプト側の版記が必要。

### 17.10 最短チェックリスト（書く直前）
パス妥当 / 秘密なし / 仮説と確定を混同しない / K承認または委任 / changelog / 改訂なら版更新。
