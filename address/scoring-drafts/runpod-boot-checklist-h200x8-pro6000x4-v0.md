## A. 水200（H200）×8 — 品質寄り本命

### A1. 調達・配置
- [ ] RunPodで **H200 / 水200 が8枚** 同一構成で確保（できれば同一ノード or 低遅延接続）
- [ ] 単価確認 ~$4.59×8 ≈ **$36.7/h**
- [ ] ドライラン予算: 2hなら ≈$73、6hなら ≈$220
- [ ] 8枚がバラノードに割れた場合の **ノード間帯域** を確認（弱いなら中止基準）
- [ ] OS: 近時の Ubuntu + NVIDIA driver + CUDA（H200対応版）

### A2. ソフトウェア
- [ ] NVIDIA driver / `nvidia-smi` で8枚見える
- [ ] Docker または conda
- [ ] 推論鯖: **vLLM** または **SGLang**（最新安定）
- [ ] NCCL テスト（多枚）: 簡単な allreduce が通る
- [ ] （任意）Ray を使うなら head/worker の時刻同期

### A3. モデル選定（どちらか明記）
- [ ] **経路1**: DeepSeek-V3 / R1 系（FP8寄り、8×H200が文献上の定石クラス）
- [ ] **経路2**: Llama 3.1 405B（高品質なら枚数増やす／量子化なら要再計算）
- [ ] ダウンロード完了チェック（サイズ・チェックサム）
- [ ] 変換が必要なら事前に（一晩かかりうる）

### A4. 起動パラメータ（机上の型）
例（イメージ・要調整）:
```bash
# 同一ノード 8GPU の例（モデル名は選定後に置換）
vllm serve <MODEL> \
  --tensor-parallel-size 8 \
  --max-model-len <8192〜> \
  --gpu-memory-utilization 0.90 \
  --trust-remote-code
```
- [ ] `tensor-parallel-size` が実GPU数と一致
- [ ] マルチノードなら `pipeline-parallel-size` / Ray 手順を別紙で固定
- [ ] KV長を最初は短め（8192）→余裕見て延長
- [ ] FP8対応フラグが環境で要る場合は確認

### A5. 健全性チェック

## B. RTX Pro 6000 ×4 — 予算寄り（量子化前提）

### B1. 調達・配置
- [ ] **RTX Pro 6000 ×4**（96GB×4=384GB）
- [ ] 単価確認 ~$2.09×4 ≈ **$8.36/h**
- [ ] ドライラン予算: 2h≈$17、6h≈$50
- [ ] できれば同一マシン（NVLink/良いPCIe）
- [ ] ドライバが Pro 6000 対応か確認

### B2. ソフトウェア
- [ ] `nvidia-smi` で4枚
- [ ] vLLM / SGLang / または llama.cpp・ExLlama系（量子化方針に合わせる）
- [ ] NCCL 4GPU テスト

### B3. モデル選定（必須で量子化方針）
- [ ] **推奨机上**: Llama 405B **INT4/AWQ/GPTQ系**（重み~200–243GB → 384GBに理論収まり）
- [ ] または 70B×複数専門家ではなく「大1本INT4」を先に検証
- [ ] DeepSeek 671B FP8は **4×96GBでは足りない**（机上×）→ 狙わないか、大幅オフロード前提で別紙
- [ ] 量子化方式と品質低下を事前に受け入れる（F★保証なし）

### B4. 起動パラメータ（机上の型）
```bash
vllm serve <MODEL_INT4> \
  --tensor-parallel-size 4 \
  --quantization <awq|gptq|...> \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.88
```
- [ ] 量子化オプションがモデルと一致
- [ ] 最初の `max-model-len` は **4096** から
- [ ] OOM時: len短縮 → util下げる → より強い量子化、の順

### B5. 健全性チェック
- [ ] 4枚に負荷分散
- [ ] `/v1/models` OK
- [ ] 短文生成OK
- [ ] 中文脈（4k）OK
- [ ] 品質スモーク: 同じ10問をAPI ChatGPT（または既知回答）と目視比較
- [ ] tok/s 記録（H200×8より遅くて正常）

### B6. 期待値コントロール
- [ ] 「安い＝ChatGPT級」と書かない
- [ ] 成功定義は「起動＋INT4で応答＋テスト10問が実用」
- [ ] 失敗定義は「OOM連続／意味崩壊／$/答が高すぎ」

### B7. 止め方
- [ ] 同上（停止・破棄・費用メモ）
