````
## 具体的な勉強法

### 1. まず論文全体を理解する

最初から数式や専門用語を調べません。

読む順番は次の通りです。

1. タイトル
2. Abstract
3. Introductionの最後
4. 図1
5. Conclusion
6. Method

この段階では、次の5つだけ答えられれば十分です。

- 何が問題なのか
- 既存手法の何が弱いのか
- 何を提案したのか
- 何が改善したのか
- どの条件で有効なのか

### 2. 用語を3種類に分ける

すべての用語を覚える必要はありません。

- A：理解しないと論文が読めない用語
- B：理解すると内容が深まる用語
- C：今回は無視してよい用語

1本の論文で、最初にAランクを5〜10個だけ選びます。

### 3. 用語を「辞書」ではなく「機能」で覚える

例えば「Attention」を次のように覚えます。

- 一言：入力のどこを見るべきかを計算する仕組み
- 解決する問題：文中の重要な単語同士の関係を捉える
- 入力：トークンのベクトル
- 出力：重要度を反映した新しいベクトル
- 例：「彼は銀行に行った」の銀行が、金融機関か川岸かを文脈から判断する
- 関連用語：Query、Key、Value、Transformer
- この論文での役割：どの部分に使われているか

「意味」だけでなく、「何の問題を解決し、入力と出力が何か」を覚えるのが重要です。

### 4. ChatGPTにすぐ答えさせない

以下のプロンプトを使ってください。

```text
あなたはLLM論文の家庭教師です。

この論文を理解したいので、すぐに答えを説明しないでください。
私が自分で考えられるように、段階的に質問してください。

ルール：
- 一度に扱う専門用語は最大5個
- 各用語について「一言の意味」「解決する問題」「入力と出力」「具体例」を説明
- 数式は、まず直感、その後に変数の意味、最後に式を説明
- 論文に書いてあることと、一般的な知識を分ける
- 私が理解したか確認するため、最後に3問出題
- 私の回答が間違っていたら、どこが間違いか具体的に指摘する

まず、この論文の全体像を5文以内で説明し、その後、理解に必須の用語を5つだけ選んでください。
```

### 5. Ankiには「定義」ではなく「質問」を入れる

悪いカード：

> MoEとは何か？

良いカード：

> MoEは、なぜすべてのパラメータを毎回使わず、一部のExpertだけを使うのか？

答え：

> 計算量を抑えながら、モデルの総パラメータ数を増やせるため。

この形式なら、論文を読むときに使える知識になります。
````

````
## NotebookLMで論文を学ぶ方法

NotebookLMは、論文PDFや補足資料を読み込ませ、資料に基づく質問、学習ガイド、クイズ、フラッシュカードを作る用途に向いています。[Google公式の学習機能説明](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/)  
音声解説も作れますが、これは初回学習より復習用に使うべきです。[Audio Overview公式説明](https://blog.google/innovation-and-ai/products/notebooklm-audio-overviews/)

### おすすめ手順

1. 1つのNotebookに論文を詰め込みすぎない  
   最初は「論文本体・補足資料・代表的な比較論文」の3つ程度。

2. 最初に自分をテストする

```text
私はLLM初心者です。
この論文を説明する前に、理解度を確認するための質問を5問出してください。
すぐに答えを表示せず、私の回答を待ってください。
```

3. 次に論文の全体像を確認する

```text
この論文について、以下を初心者向けに説明してください。

1. 何が問題なのか
2. 既存手法の限界
3. 提案手法
4. 何が改善したのか
5. どの条件では効果が弱いのか
6. 実験結果の根拠となるページや図

論文に書かれている事実と、あなたの一般的な推測を分けてください。
```

4. Figure 1を最初に理解する

```text
Figure 1を、数式なしで説明してください。

- 入力は何か
- どの処理を通るか
- 出力は何か
- 既存手法との違い
- この図だけでは分からない点

各説明にページ番号または図番号を付けてください。
```

5. 用語を10個だけ抽出する

```text
この論文を理解するために必須の専門用語を10個だけ選んでください。

各用語について、
- 一言の意味
- 何の問題を解決するか
- この論文内での役割
- 初心者が混同しやすい用語
を説明してください。
```

6. 数式は最後に扱う

```text
この数式を次の順で説明してください。

1. この式は何を最適化しているのか
2. 各変数の意味
3. 数値を入れた簡単な例
4. 式を使う理由
5. この式の限界

いきなり記号の説明から始めないでください。
```

7. 最後にクイズを解く

```text
この論文について、VCや研究者から聞かれそうな質問を10問出してください。
私が回答するまで正解を表示しないでください。
回答後は、正しい点・不足点・誤解を分けて評価してください。
```

NotebookLMのフラッシュカードはそのまま信じてAnkiへ入れるのではなく、間違いを確認してから登録してください。論文の学習では、音声を聞いて「分かった気になる」ことが最大の落とし穴です。必ず最後に、自分の言葉で「この論文は誰の何を改善したのか」を3分で説明してください。
````

```
## ユニコーンに近づく方向

汎用検索ルーターではなく、次のような縦型プロダクトを最初に作る方が可能性があります。

> AIエージェント向け  
> Global Product Compliance & Market Access Graph

例えば、

- HSコード
- ECCN
- 関税
- 輸出入規制
- 制裁対象
- 認証
- 必要書類
- 発効日
- 国・製品・用途・取引相手の関係

を、出典・更新日時・適用期間付きで返す仕組みです。

ここでは単なる検索ではなく、

> AIが誤った情報で判断しないための、監査可能な証拠基盤

を売れます。

この場合、差別化は以下になります。

- 合法的に利用できるデータ
- 正規化された独自データ
- 更新・発効日管理
- 引用元の検証
- 企業・製品・規制のEntity Resolution
- 顧客専用データとの統合
- 実業務での正解率データ
- AIエージェントの判断ログ

ここまで作れば、検索APIではなく「業務インフラ」になります。
```

````
## Fuguとの共通点と違い

Sakana AIのFuguは、単に複数のLLM APIを呼び出しているだけではありません。

Fuguの中核は、

- 問題を分解する
- 複数モデルへ仕事を割り振る
- モデルごとの得意分野を使い分ける
- 結果を統合する
- 失敗時に再試行・再ルーティングする

というオーケストレーションです。[Sakana AI公式](https://sakana.ai/fugu/)、[Fugu技術報告](https://arxiv.org/html/2606.21228v1)

あなたの事業に置き換えると、こうなります。

| Fugu | あなたの事業 |
|---|---|
| 外部LLM | Exa、Tavily、Brave、Parallel、専門DB API |
| モデル選択 | 検索エンジン・DB・検索方式の選択 |
| エージェント協調 | Query分解・並列検索・再検索 |
| 回答統合 | 重複除去・再ランキング・証拠統合 |
| Fuguの学習資産 | 検索品質・コスト・遅延・顧客フィードバック |

つまり、目指すべきは「検索APIの代理店」ではなく、

> 検索・DB・証拠を最適に組み合わせるRetrieval Orchestrator

です。

## ただし、3つの重大な問題があります

### 問題1：無料枠を分割する価格設計は危険

Exaは現在、登録時クレジットと月額無料クレジットを提供しています。Tavilyも月1,000クレジットの無料枠を提供しています。[Exa料金](https://exa.ai/pricing)、[Tavily料金](https://www.tavily.com/pricing)

しかし、これを利用者数で割って無料提供する発想は、事業の原価設計としては弱いです。

理由は、

- 無料枠は変更・停止される
- APIごとに利用制限が違う
- 複数ユーザーへの再提供が許可されているとは限らない
- 本番利用には有料プランが必要な場合がある
- Fugu型に複数APIを呼ぶと原価が急増する

ためです。Tavilyの公式ドキュメントでも、本番キーには有料プランまたは従量課金が必要と説明されています。[Tavily API制限](https://docs.tavily.com/documentation/rate-limits)

無料枠は「原価の供給源」ではなく、

> 自社が負担するマーケティング費用

として扱うべきです。

### 問題2：外部APIを組み合わせただけでは差別化にならない

顧客は当然こう聞きます。

> OpenRouterとExaを直接使えばいいのでは？

この質問に答えられなければ、単なる中継サービスです。

あなたが自社で持つべきものは、巨大な検索DBではありません。最低限、以下は初日から自社資産にする必要があります。

- Query分類
- 最適検索先の選択ポリシー
- 検索結果の評価
- 重複除去
- 再ランキング
- 引用の正確性検証
- コスト・遅延の最適化
- 失敗時のフォールバック
- 顧客ごとの評価データ
- 検索ログと改善履歴

ここが「あなたのFugu」です。

### 問題3：「シェアを取る」はB2B APIでは少し間違っている

一般消費者向けサービスなら、無料ユーザーを大量に集めることに意味があります。

しかしB2Bの検索インフラでは、

- 10,000人の無料ユーザー
- 10社の有料顧客
- 3社の本番API組み込み

なら、後者の方がはるかに価値があります。

重要なのは登録者数ではなく、

- 継続API利用
- 顧客システムへの組み込み
- 有償利用
- 低い解約率
- 顧客固有の評価データ
- 利用量の増加

です。

「シェアを取る」より、

> 顧客の本番ワークフローに入り込む

ことを目標にしてください。

## 推奨する価格構造

無料枠をプロバイダー無料枠から逆算するのではなく、まず自社の原価を計算します。

```text
1リクエストの実原価
=
検索API費用
+ DB API費用
+ LLM費用
+ 再試行費用
+ ストレージ費用
+ 通信費
+ 決済費
```

そのうえで、

```text
販売価格
=
実原価 ÷ (1 - 目標粗利率)
```

例えば目標粗利率70％なら、原価1円の処理は最低でも約3.33円で販売する必要があります。

料金体系は次が合理的です。

- Free：月20〜50回程度、開発者向け
- Starter：月額＋一定クレジット
- Pro：月額＋大量クレジット＋高いレート制限
- API：最低月額料金＋従量課金
- Enterprise：専用ルーティング、VPC、監査ログ、SLA

クレジットは、プロバイダーのAPI単位ではなく、自社の処理負荷単位にしてください。

例えば、

- Basic Search：1クレジット
- Multi-Search：5クレジット
- Deep Research：10〜20クレジット
- 専門DB照会：データソース別に設定

という形です。
````

````
|---|---|

| RAGRouter-Bench | 「質問とDBの相性」を評価するベンチマーク。検索方式に万能解はないことを示し、SearchGatewayの評価設計に使える |
| T-GRAG／STAR-RAG | 時間軸付き知識グラフを使い、古い情報・時間の矛盾・重複を抑える。規制、価格、許認可、企業イベントに適する |
| ALCE | URLが付いているだけでは引用とは言えず、主張を実際に支えているかを評価する考え方。証拠統合・引用検証に使える |

[RAGRouter-Bench](https://arxiv.org/abs/2602.00296)も、質問とコーパスの組み合わせによって最適なRAG方式が変わり、万能な検索方式はないと報告しています。

- LLMの内部知識だけでは不足する質問

反対に、単純な一般知識や短い計算では、外部検索はコストと遅延を増やすだけです。

- `originates_from`
- `destined_to`
- `has_end_use`

### 必須の時間情報

- `valid_from`
- `valid_to`
- `published_at`
- `retrieved_at`
- `superseded_by`
- `source_revision`

「現在有効か」「いつの時点で有効だったか」を扱えることが、通常のRAGとの差別化になります。

## CloudflareでTemporalGraphRAGは使えるか

使えます。ただし、CloudflareにTemporalGraphRAGという完成機能があるわけではありません。複数サービスを組み合わせて実装します。

| 役割 | Cloudflare |
|---|---|
| API・Router | Workers |
| 時間軸・関係・メタデータ | D1 |
| 元文書・HTML・スナップショット | R2 |
| ベクトル検索 | Vectorize |
| 更新処理 | Queues |
| 同時実行・テナント状態 | Durable Objects |
| キャッシュ | KV |

D1はSQLite互換のサーバーレスSQL、Vectorizeはベクトル検索とメタデータフィルタ、R2は大容量オブジェクト保存、Queuesは非同期処理に使えます。[Cloudflareストレージ選択](https://developers.cloudflare.com/workers/platform/storage-options/)、[D1](https://developers.cloudflare.com/d1/)、[Vectorize](https://developers.cloudflare.com/vectorize/)、[Queues](https://developers.cloudflare.com/queues/)

ただし、D1はネイティブなグラフデータベースではありません。

そのため初期版では、

- D1にノード・エッジ・時間情報を保存
- Vectorizeで候補文書を検索
- D1で1〜2 hopの関係をたどる
- Workersで時間条件を適用
- R2の原文・証拠箇所を返す

という構成が現実的です。

巨大なグラフの深い探索を最初から行う必要はありません。最初は「時間軸付きリレーショナルDB＋グラフ投影＋ベクトル検索」で十分です。
````

````
## 1. OpenClawへの入り方

### 最優先：DataQorix MCP Server

OpenClawから以下のツールを呼び出せるようにします。

| ツール | 用途 |
|---|---|
| `dataqorix_search` | 通常のWeb・ニュース・専門検索 |
| `dataqorix_entity` | 企業・人物・製品・法人番号の同定 |
| `dataqorix_evidence_pack` | 複数ソースから証拠パック作成 |
| `dataqorix_verify` | 回答中の主張と証拠の照合 |

検索リクエストには、次の情報を含めます。

- 国・地域
- 業界
- 最新性
- 情報源の信頼度
- 予算上限
- 許可するDB
- 顧客固有のポリシー
- 引用必須かどうか

OpenClaw向けの売り文句は次です。

> OpenClawの行動能力に、DataQorixが業界データ・地域データ・証拠評価を提供します。ブラウザで見つけるだけではなく、企業調査・法規制・医療・金融情報を、出典付きで返せます。

### 次点：OpenClaw Skill

Skillで、次のようなルールを与えます。

- 企業調査はDataQorixを最初に使う
- 法律・医療・金融は公式DBを優先する
- 1つの検索結果だけで断定しない
- 引用・取得日時・管轄地域を回答に含める
- DataQorixが失敗した場合のみ一般Web検索へフォールバックする

### 注意点

OpenClawの標準Web検索プロバイダーをDataQorixへ直接置換できるかは、現在の公式仕様だけでは断定できません。したがって、最初は「MCP Server」として接続し、将来的に互換検索APIアダプターを提供するのが安全です。

また、OpenClawのローカルブラウザはログイン済みの顧客環境へアクセスできます。DataQorixはそこに入り込まず、外部の公開情報・契約DB・顧客が許可したAPIだけを担当するのがよいです。
````
