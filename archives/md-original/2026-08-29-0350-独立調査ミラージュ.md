絶対原則

• 発見候補を証明済みと呼ばない。
• 実験前にイベント時刻、target ID、world label、hidden residual、将来フレームをruntimeへ渡さない。

• 公開観測・Gold・prediction/traceを物理的にも論理的にも分離する。
• 全Frame全画素baselineと同一の正解定義・入力・seed・停止条件で比較する。
• 削減率ではなく、再現率・非回答の安全性・反証耐性・総コストを同時に評価する。
• 失敗は隠さず、FAILとして保存し、次の反証ケース生成に利用する。
• 外部ネットワーク、個人データ、実センサー、R6、未承認の計算資源を使わない。
• CPU・Python標準ライブラリ中心で、決定的Replay可能な実験を行う。

基本Toy World群

最低限、次の世界を実装する。

• W1: target eventと完全な値が公開映像から導出可能
• W2: structured event/relationは導出可能だが、random residualは独立・不可視
• W3: target event/valueが公開映像と独立し、正答はNOT_DERIVABLE

毎回、以下の軸を組み合わせて新しいWorldを生成せよ。

• event duration: 1, 2, 5, 10, 30 frames

• phase offset
• target permutation
• distractor motion
• occlusion
• crossing / identity ambiguity
• global camera shift
• descriptor/relation combination
• seen / held-out combination
• frame rate、解像度、ROIサイズ
• relation transitionの前後にある無関係な変化

各Worldには、公開観測、Gold、生成seed、World構成、期待される導出可能性を記録せよ。

Counterexample-Guided Discovery Loop

次のループを停止せず反復せよ。

1. 仮説生成

新しい候補原理を1つだけ明文化する。

例:

• persistent stateの部分更新
• relation changeを一次Addressにする
• global sentinelからROIを自動構成する
• target候補を予測的に優先する
• 不確実性が増えたSlotだけ再検証する

仮説ごとに、何が変わり、何を測れば反証できるかを宣言する。

2. 最小実装

候補を最小のCPU Toy Policyとして実装する。

runtimeの入力はpublic observationだけに限定する。runtime関数・CLI・環境変数・パス・importにGold、world、residual、generator、event timestamp、target membershipを入れてはならない。

3. 反証World生成

まず最小Worldで試し、失敗・過大コスト・不変性違反が出たら、その失敗を再現する最小反例を縮約する。

その後、次のいずれか1変数だけを変異させる。

• timing
• density
• occlusion
• distractor
• camera shift
• identity ambiguity
• descriptor/relation
• target order

複数条件を同時に変えず、どの変異が原因だったか追跡可能にする。

4. Leakage / Oracle Gate

各候補について自動監査する。

• AST上の禁止識別子・import・関数引数・keyword引数
• CLIのGold/world/residual/generatorオプション
• open、Path、environment、filenameからのWorld/answer漏洩
• public JSONの禁止キー
• opaqueでないepisode_id
• public/gold/prediction間のepisode_id不一致
• target-track-object permutationでの出力変化
• event timestampやtarget IDを直接参照する処理
• future frame、Gold crop、oracle cropを利用する処理

1つでも違反した候補は性能評価へ進めず、即FAIL保存する。

5. 公平なコスト計測

最低限、次のraw cost vectorを記録する。

• decoded_pixels
• sentinel_pixels
• detail_pixels
• address_operations
• verification_operations
• memory_operations

Oracleで既知の変化時点だけを読む処理は禁止する。

global sentinel、Address生成、query、verification、memory更新をすべて課金し、baselineと同一粒度で比較する。

6. 多目的選抜

候補を単一の削減倍率で選抜しない。

最低条件:

• W1 structured recall ≥ baselineの95%
• W2 structured scoreとresidual abstentionを分離報告
• W3 confident answer rate = 0を目標
• W1 false abstentionを別途報告
• raw costが全項目非負
• deterministic replay一致
• target permutation invariance
• 10倍削減はengineering screenに限定し、scientific gateを緩和しない

選抜スコアは、recall、safe abstention、held-out robustness、raw cost、leakage risk、counterexample countを含むPareto形式にする。

7. Evidence / FAIL保存

各試行で以下を必ず保存する。

• hypothesis
• implementation identifier
• world configuration
• random seed
• public hash
• Gold hash
• prediction/trace hash
• raw cost vector
• metrics
• leakage audit result
• permutation result
• counterexample
• verdict: PASS_CANDIDATE, FAIL_LEAKAGE, FAIL_ORACLE, FAIL_RECALL, FAIL_W3, FAIL_COST, FAIL_REPLAY
• next mutation

失敗時も、再現可能な最小ケースと失敗理由を保存する。

探索を加速する方法

• 既知の失敗ケースを回帰テスト化する。
• World生成と候補評価は、seed単位で独立実行する。
• 同一入力・同一候補の結果はhashでキャッシュする。
• 高コスト候補は早期棄却するが、棄却条件と未実行軸を記録する。
• 小さいWorldで通過した候補だけ、track数・frame数・変化密度を拡大する。
• 見かけの倍率が高くても、監視費用・Address費用・verification費用込みで再計算する。
• 反例を最優先で次のWorld生成へ反映する。
• 既知Worldだけで連勝した候補より、未知のdescriptor/relationと強い反例を通過した候補を優先する。
