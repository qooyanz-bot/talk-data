Skillでいう**「ゼロショット対応（Zero-shot）」**とは、

> **事前にそのタスク専用の学習や具体例（Few-shot）を与えなくても、Skillの説明や仕様だけで実行できるように設計されている**という意味です。

AI開発、とくにClaude SkillsやCodex Skillsでは重要な考え方です。

### 例

#### ゼロショット対応していないSkill

```
このSkillはブログを書きます。
```

これだけではAIは、

- どのような構成なのか
- 文体は？
- 見出しは？
- SEOを考えるのか
- 最後にCTAを書くのか

などが分からず、品質が安定しません。

---

#### ゼロショット対応したSkill

```
目的
・SEO記事を作成する

入力
・タイトル
・ターゲット
・キーワード

出力
1. 導入
2. H2
3. H3
4. まとめ
5. CTA

文体
・ですます調
・専門用語は説明する
・PREP法を基本とする

禁止事項
・根拠のない断定
・冗長な表現
```

これだけ書かれていれば、

AIは例を見なくてもかなり正確に動けます。

これが**ゼロショット対応**です。

---

## Few-shotとの違い

### Zero-shot

仕様だけ。

```
入力：
企業名

出力：
企業概要
競合
ニュース
採用情報
```

AIは仕様だけで動きます。

---

### Few-shot

仕様＋実例があります。

```
入力
OpenAI

出力例
企業概要...
競合...
ニュース...
```

実例があるので品質は上がりますが、Skill自体が長くなります。

---

## なぜゼロショット対応が重要なのか

最近の高性能LLM（GPT-5.5/5.6、Claude、Grok、Muse Sparkなど）は推論能力が高いため、

- 目的
- 入力
- 出力形式
- 制約
- 評価基準

を明確に定義すれば、具体例がなくても高品質な結果を生成できることが多くなっています。

そのため、Skillは**「例を大量に書く」のではなく、「仕様書として曖昧さなく記述する」**方向が主流になっています。

---

## あなたが作ろうとしているFugu型オーケストレーションとの相性

企業ナレッジベース用のSkillであれば、各Skillをゼロショット対応にすると保守性が高くなります。

例えば、

- IR取得Skill
- 採用分析Skill
- ニュース分析Skill
- 特許分析Skill
- SNS分析Skill

それぞれに「入力」「処理手順」「期待する出力」「品質基準」を定義しておけば、Plannerは必要なSkillを選んで組み合わせるだけで動作できます。新しいLLMへ切り替える場合も、実例を大量に書き換える必要がなく、Skillの仕様を維持したまま流用しやすいのが利点です。
