## 全体構成

通常のCodex Desktopは

```
Codex Desktop
      │
 OpenAI API
```

という構成です。

OpenCodexを導入すると

```
Codex Desktop
      │
   OpenCodex Proxy
      │
 ┌────┼──────────────┐
 │    │              │
OpenAI Anthropic   Google
 │
OpenRouter
 │
xAI
```

になります。

つまりCodex DesktopはOpenAIだけではなく、

- OpenAI
- Anthropic
- Google
- OpenRouter
- xAI

へ自由にルーティングできます。

| 作業 | おすすめモデル |
|------|-----------------|
| Project Bible | gpt-5.6-terra |
| SaaS設計 | gpt-5.6-sol |

| リポジトリ解析 | kimi-k3 |
| コストを抑えた大量コード生成 | deepseek-v4-flash |

## 私ならさらに改善します

12モデルでも実用的ですが、開発効率を重視するなら**「用途別」にさらに絞る**ことを勧めます。

例えば以下の8モデル程度なら、ほとんど迷わず選べます。

- gpt-5.6-terra（大規模設計）
- gpt-5.6-sol（実装・設計）
- gpt-5.5（汎用）
- gpt-5.3-codex-spark（高速コーディング）
- claude-sonnet-5（長文・レビュー）
- kimi-k3（大規模コード解析）
- deepseek-v4-flash（低コスト実装）
- grok-4.5（アイデア・市場分析）

EnterpriseOSのような長期・大規模プロジェクトでは、モデルを増やすことよりも、「どの作業にどのモデルを使うか」を固定したほうが、迷いが減り、開発速度も安定します。
