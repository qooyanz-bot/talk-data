`/goals` ではなく、正しくは **`/goal`** です。Codexの「Goal mode」は、Codex app・IDE extension・CLIで使える機能で、「達成条件」を置いて、Codexに検証しながら継続作業させるためのものです。citeturn793900view0

## まず使い方

Codexを最新版にします。Goalは **Codex 0.128.0以降**で利用できます。citeturn735691view0

```bash
npm install -g @openai/codex@latest
codex --version
```

または Homebrew なら、

```bash
brew update
brew upgrade --cask codex
codex --version
```

## 基本コマンド

```text
/goal <達成したい状態>
```

例：

```text
/goal ログイン画面のバグを修正し、関連テストがすべて通る状態にする
```

管理コマンドはこれです。citeturn735691view0

```text
/goal          現在のGoalを見る
/goal pause    一時停止
/goal resume   再開
/goal clear    解除
```

## `/goal` と普通の指示の違い

普通の指示は「次にこれをやって」で終わります。  
`/goal` は「この条件が満たされるまで、検証しながら進めて」です。Codexはテスト、ベンチマーク、ファイル変更、ログなどの証拠を見て、完了か継続かを判断します。citeturn735691view2

## 良い `/goal` の書き方

弱い例：

```text
/goal パフォーマンスを改善して
```

これはダメです。何をもって成功か不明だからです。

強い例：

```text
/goal checkout APIのp95レイテンシを120ms未満にし、既存のcorrectness test suiteがすべて通る状態にする。checkout benchmarkで検証し、変更内容・ベンチ結果・次に試したことを各イテレーションで記録する。ベンチマークが実行できない場合は、試した手順・ブロッカー・次に必要な入力を報告して停止する。
```

OpenAIの推奨パターンは、**成果・検証方法・制約・対象範囲・反復方針・停止条件**を入れることです。citeturn735691view2

## テンプレ

そのまま使うならこれ。

```text
/goal <最終的に達成したい状態>。<テスト・ベンチ・ビルド・成果物>で検証する。<壊してはいけない条件>は維持する。対象は<触ってよいファイル・機能・範囲>に限定する。各ステップで、変更内容・検証結果・次に試すことを記録する。達成不能またはブロックされた場合は、試したこと、得られた証拠、ブロッカー、次に必要な入力をまとめて停止する。
```

## 実用例

### バグ修正

```text
/goal 決済完了後に注文ステータスが更新されないバグを修正する。関連する注文・決済テストを実行して検証し、既存APIの互換性は壊さない。原因調査、最小修正、テスト追加、検証結果の順に進める。再現できない場合は、確認したログ・仮説・不足している情報を報告して停止する。
```

### フロントエンド修正

```text
/goal 商品一覧ページのモバイル表示崩れを修正する。対象は商品一覧ページと関連CSS/コンポーネントに限定する。ローカルビルドと該当ページの表示確認で検証する。PC表示を regress させない。修正後に変更点と確認結果をまとめる。
```

### リファクタ

```text
/goal userServiceの責務を分割し、既存テストがすべて通る状態にする。外部APIの振る舞いは変更しない。変更範囲はuserService、関連repository、関連テストに限定する。各分割後にテストを実行し、失敗した場合は原因を特定してから次へ進む。
```

## 使うべき場面・使わない場面

使うべきなのは、**テスト・ベンチマーク・ビルド・成果物などで完了判定できる複数ステップ作業**です。OpenAIも、性能改善、flaky test調査、依存関係移行、バグ調査、複数ステップのリファクタ、研究調査などを良い候補として挙げています。citeturn735691view0

逆に、

```text
/goal いい感じにして
/goal 全体的に改善して
/goal もっと良くして
```

これは弱いです。Codexが「完了」を検証できないので、作業が散らかります。

結論：`/goal` は「お願い」ではなく、**完了条件付きの作業契約**として書くのがコツです。  
雑に投げるなら普通のプロンプト、完了まで詰めさせるなら `/goal` です。
