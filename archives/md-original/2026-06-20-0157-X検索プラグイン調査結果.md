````
## 調査結果（2026年6月21日）

結論から言うと、**Claude CodeとCodexの両方でX検索を使うなら、専用「プラグイン」よりMCPサーバーを入れるのが正解**です。今回確認できた範囲では、両社が提供するX検索専用の公式プラグインは見つかりませんでした。

### 1. 最有力：`Infatoshi/x-mcp`
Claude Code・Codexの両方に対応した、X API v2ベースのMCPサーバーです。投稿検索、ユーザー検索、タイムライン取得、投稿分析などができます。Claude CodeとOpenAI Codexの両方の設定例がREADMEにあります。 citeturn797662view0turn593114view1

- GitHub: `Infatoshi/x-mcp`
- 検索機能: `search_tweets`
- 対応: Claude Code / Codex CLI・IDE / Cursor ほか
- 必要なもの: X Developerアカウント、X APIキー群
- 注意: 投稿・削除・リポストまで可能なので、**検索用途だけならXアプリをRead-only権限で作るべき**です。 citeturn396880view0turn577051view0

X公式APIの検索は直近7日間の投稿検索エンドポイントを使えます。現在のX APIは従量制で、投稿読み取りは1件あたり$0.005です。 citeturn577051view8turn797662view11

### Claude Codeへの設定例

```powershell
claude mcp add `
  --scope user `
  --transport stdio `
  --env X_API_KEY=YOUR_API_KEY `
  --env X_API_SECRET=YOUR_API_SECRET `
  --env X_BEARER_TOKEN=YOUR_BEARER_TOKEN `
  --env X_ACCESS_TOKEN=YOUR_ACCESS_TOKEN `
  --env X_ACCESS_TOKEN_SECRET=YOUR_ACCESS_TOKEN_SECRET `
  x-twitter `
  -- node "C:\dev\x-mcp\dist\index.js"
```

事前にリポジトリを取得してビルドします。

```powershell
git clone https://github.com/INFATOSHI/x-mcp.git C:\dev\x-mcp
cd C:\dev\x-mcp
npm install
npm run build
```

Claude Codeはローカルstdio MCPを `claude mcp add` で追加でき、`/mcp` で接続状態を確認できます。 citeturn577051view3

### Codexへの設定例

```powershell
codex mcp add x-twitter `

  --env X_API_SECRET=YOUR_API_SECRET `
  --env X_BEARER_TOKEN=YOUR_BEARER_TOKEN `
  --env X_ACCESS_TOKEN=YOUR_ACCESS_TOKEN `

Codexは `codex mcp add` または `~/.codex/config.toml` でMCPを追加できます。さらに `enabled_tools` / `disabled_tools` によるツール制限が可能なので、検索専用に絞るなら有効化するのは `search_tweets`、`get_tweet`、`get_user`、`get_timeline` 程度に限定すべきです。 citeturn577051view5turn396880view4

### 2. Claude Code寄り：`Xurl-MCP`
X公式のCLI `xurl` をラップしたClaude Codeプラグインです。`xurl` 自体はX Developer Platformの公式CLIで、OAuth 1.0a / OAuth 2.0に対応しています。MCP側は第三者製ですが、認証とAPI呼び出しは公式CLI経由です。 citeturn961638search2turn577051view4turn577051view2

- GitHub: `mrdulasolutions/Xurl-MCP`
- Claude Codeでは `claude plugin install .` で導入可能
- 検索・投稿・トレンド・DM・リストなど49ツール
- Codexでも標準stdio MCPとして手動設定すれば利用可能
- Windowsでは `npm install -g @xdevplatform/xurl` で公式CLIを導入できます。 citeturn593114view5turn396880view1turn396880view2

これは便利ですが、**検索だけに49ツールは過剰**です。X運用自動化まで視野に入れる場合だけ候補です。

---

### 3. 大量リサーチ向け：`Xquik x-twitter-scraper`
Claude Code・Codex双方にSkillとして導入でき、X検索、アカウント調査、フォロワー抽出、監視、Webhook、MCP連携まで扱えます。X APIを直接使うのではなく、Xquikの外部データ基盤を使う方式です。 citeturn577051view6turn593114view9

- GitHub: `Xquik-dev/x-twitter-scraper`
- Claude Code配置先: `.claude/skills/x-twitter-scraper`
- Codex配置先: `.agents/skills/x-twitter-scraper`
- 検索は `from:`、`since:`、`until:`、ハッシュタグ、ORなどの演算子に対応
- 検索結果1件あたり1クレジット課金。 citeturn593114view10turn396880view3

こちらは「バズ投稿の収集」「競合アカウント監視」「週次の話題抽出」のようなマーケ用途には強いです。ただし、Xの認証情報を自分で直接持つ公式API方式より、第三者サービス依存が増えます。

## 推奨順位

1. **検索・分析中心**  
   `x-mcp` + XアプリをRead-onlyで作成  
   → Claude CodeとCodexを共通化できる。

2. **X投稿・分析・トレンドもAIに任せたい**  
   `Xurl-MCP`  
   → 公式X CLIベース。ただし強い権限を渡すため注意。

3. **SNSリサーチや大量収集を事業化したい**  
   `Xquik`  
   → 検索・監視・抽出ワークフロー向け。

## 実務上の注意

X検索をAIエージェントに任せるなら、**普段使いのXアカウントに投稿権限を渡したまま、広範なMCPを接続するのは避けるべき**です。外部投稿内容にはプロンプトインジェクションが混ざり得ます。Claude Code公式も、外部コンテンツを取得するMCPはプロンプトインジェクションのリスクがあると明示しています。 citeturn577051view3

最初は専用X Developer Appを作り、Read-only権限、少額のAPI利用上限、検索専用ツールの許可リストで始めるのが安全です。

X API料金・MCP更新の週次監視も設定できます。
````
