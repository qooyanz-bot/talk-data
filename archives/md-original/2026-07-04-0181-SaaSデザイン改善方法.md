````
率直に言うと、今の問題は「Codexのデザインセンスが悪い」ではなく、**あなたの指示が“作ってほしい画面”ではなく“なんとなく良い感じのSaaS”になっている可能性が高い**です。  
Codexに「モダンに」「SaaSっぽく」「使いやすく」と言うと、だいたい余計なカード、グラデーション、ヒーロー、バッジ、説明文、アニメーションを盛ります。

Codexには、**見た目の方向性より先に、削るルール・画面の目的・完了条件**を渡してください。OpenAI公式のCodexベストプラクティスでも、良い指示には「Goal / Context / Constraints / Done when」を含めるとされています。複雑なタスクでは、実装前に計画させるのも推奨されています。citeturn501317view0

## まず、こう指示してください

そのまま貼れる形で書くと、これです。

```text
このSaaSは「業務を素早く完了するための管理画面」です。
マーケティングサイトのような派手なデザインは不要です。

目的:
ユーザーが迷わず、最短手数で主要タスクを完了できるUIにしてください。

最優先すること:
- 情報の見やすさ
- 操作の分かりやすさ
- 画面遷移の少なさ
- 主要CTAの明確さ
- 不要な装飾や説明の削除

禁止:
- グラデーション、過剰な影、装飾イラスト、絵文字
- 意味のないカード分割
- ランディングページ風のヒーローセクション
- 大きすぎる余白
- 使わない統計カード
- 実装していない機能のボタン
- ユーザーが求めていないページや機能の追加
- 「それっぽい」だけの文言

デザイン方針:
- B2B SaaSの管理画面として、地味でよい
- 1画面1目的にする
- 一番重要な操作を画面上部または右上に置く
- 一覧、検索、フィルター、詳細、編集、削除の導線を明確にする
- モバイル対応より、まずデスクトップでの業務効率を優先する
- 既存のコンポーネントとデザインシステムを再利用する
- 新しいUIライブラリや依存関係は勝手に追加しない

実装前にやること:
1. 現在の画面を確認する
2. 主要ユーザーが何をしたい画面なのかを推測する
3. 不要な要素をリストアップする
4. 削除・統合・簡素化の方針を提示する
5. その後に実装する

完了条件:
- 各画面の主要アクションが3秒以内に分かる
- 余計な装飾要素が削除されている
- CTAが1画面に多すぎない
- 実装していない機能への導線がない
- lint/typecheck/buildが通る
- 変更内容を最後に箇条書きで説明する
```

## さらに強くするなら「削除優先」と明記する

Codexは放っておくと追加で解決しがちです。SaaSのUIでは逆です。**追加ではなく削除が先**です。

```text
今回は新機能追加ではなく、UI/UXの整理が目的です。
原則として「追加」より「削除」「統合」「簡素化」を優先してください。
迷った場合は、要素を増やさず、既存要素を分かりやすく並べ替えてください。
```

これを入れるだけで、かなり余計なものが減ります。

## 既存UIを直すときの指示

```text
既存のUIを、業務用SaaSの管理画面として使いやすくリファクタしてください。

まずコードを変更せず、以下をレビューしてください:
- 各画面の目的
- ユーザーが最初に見るべき情報
- 主要アクション
- 不要な装飾
- 不要な文言
- 重複している導線
- 使いにくいレイアウト
- 削除すべきコンポーネント

レビュー後、最小限の変更でUIを改善してください。

判断基準:
見た目の華やかさではなく、ユーザーが目的の操作を迷わず完了できるかで判断してください。
```

## 新規画面を作るときの指示

```text
以下の画面を作ってください。

画面名:
[例: 顧客一覧画面]

ユーザーの目的:
[例: 顧客を検索し、詳細確認・編集・ステータス変更を行う]

必要な要素:
- ページタイトル
- 主要CTA
- 検索
- 最小限のフィルター
- テーブル
- ステータス表示
- 行アクション
- 空状態
- ローディング状態
- エラー状態

不要な要素:
- ヒーローセクション
- キャッチコピー
- 装飾カード
- ダミーの分析グラフ
- 使わないサマリーカード
- 意味のないアイコン
- 未実装機能のボタン

トーン:
シンプル、実務的、控えめ、情報密度はやや高め。
```

## AGENTS.mdに固定ルールとして入れる

毎回プロンプトで同じことを言うのは無駄です。Codexは`AGENTS.md`を作業前に読み、リポジトリごとの継続的な指示として使えます。OpenAIのドキュメントでも、`AGENTS.md`はプロジェクトのルール、テストコマンド、レビュー方針、禁止事項などを置く場所とされています。citeturn501317view1  
Codexアプリでは`/init`でプロジェクト用の`AGENTS.md`の雛形を生成できます。citeturn501317view3

リポジトリ直下に、たとえばこう置いてください。

```md
# AGENTS.md

## Product principle

This project is a practical B2B SaaS application, not a marketing website.
Prioritize task completion, clarity, speed, and maintainability over visual decoration.

## UI/UX rules

- Keep screens simple, dense, and practical.
- One screen should have one primary purpose.
- One page should have one obvious primary CTA.
- Do not add decorative sections, hero areas, gradients, fake stats, illustrations, or unnecessary cards.
- Do not add features, pages, buttons, or navigation items unless explicitly requested.
- Prefer tables, forms, tabs, filters, and clear empty states over decorative layouts.
- Use existing components and patterns before creating new ones.
- Do not introduce new UI libraries or dependencies without approval.
- Japanese UI copy should be short, direct, and operational.

## SaaS screen requirements

For list screens, include only when relevant:
- title
- primary action
- search
- minimal filters
- table
- pagination
- row actions
- empty state
- loading state
- error state

For form screens:
- group fields logically
- show required fields clearly
- keep labels short
- place primary and secondary actions consistently
- avoid long explanatory text unless necessary

## Do not

- Do not create landing-page style UI inside the app.
- Do not add placeholder analytics cards unless requested.
- Do not use excessive shadows, rounded corners, animations, or large whitespace.
- Do not create fake navigation items.
- Do not hide important actions inside unclear menus.
- Do not prioritize visual novelty over usability.

## Done when

Before finishing:
- Run lint/typecheck/build if available.
- Confirm the main user task is obvious.
- Confirm unnecessary UI has been removed.
- Summarize what was simplified.
```

OpenAIのCodexカスタマイズ資料でも、`AGENTS.md`は永続的なプロジェクト指示として使い、繰り返し起きるミスやレビュー指摘をそこに追加していくのが推奨されています。citeturn501317view2

## 一番重要な考え方

あなたがCodexに言うべきことは、これです。

```text
“良い感じにして”ではなく、“ユーザーがこの画面で何を完了するのかを明確にし、それ以外を削れ”。
```

SaaSの使いやすさは、デザインの華やかさではなく、**迷わないこと・戻らなくていいこと・余計な判断をさせないこと**です。

特に管理画面なら、狙うべきは「かっこいいUI」ではなく、**退屈だけど速いUI**です。ここを間違えると、Codexは一生それっぽいだけの画面を量産します。
````
