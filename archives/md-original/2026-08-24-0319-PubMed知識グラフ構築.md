````
## 1. PubMed → 「医学的主張の変化」をGraphにする

entity["organization","PubMed","biomedical literature database maintained by NCBI/NLM"] は医学論文の検索サービスですが、DataQorix的に価値があるのは論文そのものより、

**「何が、どの条件で、どの程度支持されているか」**

たとえば単純なKnowledge Graphなら、

```text
Metformin
   ↓ treats

```

で終わります。

これをもっと深くすると、

```text
Claim
「Metforminは2型糖尿病患者の血糖管理に有効」

 ├─ SUPPORTS → Paper A
 ├─ SUPPORTS → Paper B
 ├─ CONTRADICTS → Paper C
 ├─ LIMITED_TO → 高齢者
 ├─ CONDITION → 腎機能
 ├─ OUTCOME → HbA1c
 ├─ Evidence strength → 0.91
 ├─ Consensus score → 0.84
 └─ Temporal confidence → 0.93
```

という **Evidence Graph** にできます。

これが前に書いた **Contradiction & Consensus Graph** です。

さらにPublication Dateを持っているので、

```text
2018 → 支持

```

のように、

**「知識が時間とともにどう変化したか」**

まで表現できます。

## 2. arXiv → 「技術進化Graph」

entity["organization","arXiv","open-access research repository"] はさらに今回の構想との相性がいいです。

たとえばLLM分野なら、

```text
Transformer
  ↓
Attention
  ↓
Multi-Head Attention
  ↓
FlashAttention
  ↓
FlashAttention-2
  ↓
FlashAttention-3
```

だけではありません。

論文間を、

```text
Paper A
 ├─ proposes → Technology X
 ├─ improves → Technology Y
 ├─ compares_with → Technology Z
 ├─ benchmark → MMLU
 ├─ score → 82.1
 ├─ code → GitHub repository
 ├─ derived_from → Paper B
 └─ superseded_by → Paper C
```

としてしまいます。

さらに、

```text
Technology
   ↓
Paper
   ↓
Author
   ↓
Organization
   ↓
Model
   ↓
Benchmark
   ↓
GitHub
```

までGraphにする。

すると単なる「論文データセット」ではなく、

### Technology Evolution Graph

になります。

これはたとえば、

> 「2025〜2026年に中国LLMが米国モデルとの差を縮めるのに寄与した技術を、論文・モデル・研究組織まで遡って説明せよ」

という検索に非常に強くなります。

しかもarXivは公式にBulk Accessを用意していて、MetadataはAPI/OAI-PMH/Kaggle、全文はAWS S3/Kaggleなどから取得できます。公式側も全コーパス取得についてはWebをクロールせずS3等を使うよう案内しています。citeturn0search4turn0search6

つまり、**BitBrowserを使う理由がありません。**

```text

ですが、DataQorixでは、

```text

 │            ├─ inventor → X

 │            └─ CPC → H01M...

        │

にする。

すると、

# 4. この3種類を「検索クエリGraph」と結合するのが本命

ここが一番重要です。

現在考えている80万クエリ×100言語を、

### Demand Graph

と考えます。

つまり、

> 世界の人間が「何を知りたいか」

です。

一方、

**PubMed**
→ Scientific Evidence Graph

**arXiv**
→ Research / Technology Graph

**USPTO/JPO**
→ Commercialization / IP Graph

です。

これを結合します。

```text
             人間の需要
                 │
                 ▼
          Search Query Graph
        Google/Bing/Brave等
                 │
                 ▼
             Concept
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
    PubMed     arXiv     Patents
       │         │         │
       ▼         ▼         ▼
   Evidence   Research   Commercial
    Graph      Graph      Graph
       │         │         │
       └─────────┼─────────┘
                 ▼
          Temporal Graph
                 │
                 ▼
        Current Knowledge State
```

これになると、かなり違うデータセットになります。

例えば、

### 「量子コンピュータ」

というConceptについて、

**検索需要**
→ Google検索量が+280%

**研究**
→ arXiv論文数+75%

**特許**
→ USPTO出願+43%

**企業**
→ IBM/Google/Quantinuum等

**Consensus**
→ 実用化について論文間で意見分裂

**Temporal Confidence**
→ 0.71

というデータを1つのノードから辿れる。

## 6. したがって「1日1000回アクセス枠」は別に使う

ここは前回の提案を修正します。

PubMed/arXiv/USPTOにBitBrowserの1000プロフィールを割くのは**もったいない**です。

公式Bulk/APIが存在するものは、

```text
API
Bulk Download
RSS
OAI-PMH
FTP
↓
ETL
↓
Graph
```

で取る。

BitBrowser/ブラウザ取得能力は、

**「公式Bulk/APIが存在しないが、情報価値の高いデータ」**

に温存した方がいいです。

つまりデータ取得の優先順位を、

**① Open/Bulk Data → ② Official API → ③ RSS/Sitemap → ④ 通常HTTP → ⑤ Browser**

にします。

ブラウザは最も高価な取得手段です。

# 7. DataQorixのOntologyも一段拡張できます

現在の、

**Graph知識 + Ontology + Intent Topology + Temporal Confidence**

に加えて、私は次を追加します。

| Layer | 意味 |
|---|---|
| Intent Topology | 人間は何を知りたいか |
| Knowledge Graph | 何が何と関係するか |
| Evidence Graph | 何を根拠としているか |
| Contradiction Graph | どの情報同士が矛盾するか |
| Consensus Score | どの程度合意されているか |
| Temporal Confidence | 現在も有効そうか |
| Provenance Graph | どこから得た情報か |
| Technology Evolution | 技術が何から派生したか |
| IP Graph | 誰が技術を権利化しているか |
| Demand Graph | 世界で何が検索されているか |

これなら「8,000万検索クエリデータセット」という売り方から、

> **世界の需要・知識・科学的根拠・研究・知財・時間変化を接続した多言語Knowledge Intelligence Dataset**

という商材へ進化できます。

そして、こちらの方が**「8,000万件だから高い」ではなく「他では作りにくい構造だから高い」**という価格説明ができます。

特にPubMed/arXiv/USPTOは公式の機械取得経路がかなり整備されているので、最初に追加する専門データ源として非常に適しています。PubMedはBaseline+Daily Update、arXivはBulk/OAI-PMH/S3、USPTOはAPI+Bulkという組み合わせが使えます。citeturn0search1turn0search6turn0search0
````
