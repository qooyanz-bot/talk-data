# 本来のBuilderOSはこうあるべき

BuilderOSの最大の強みは、**ページを生成することではなく、デザインシステムそのものを生成できること**です。

理想的な生成フローは次のようになります。

```
参考サイト解析
        +
ユーザー回答
        +
添付画像
        +
ブランド情報
        +
業種
        +
競合

↓

AI Designer

↓

Design DNA

・余白
・書体
・色
・角丸
・影
・Grid
・Container
・Breakpoints
・Animation
・Component Rules

↓

AI Layout

↓

Page Tree

↓

Canvas
```

こうなると、AIは「完成ページ」を作るのではなく、「そのブランド専用のデザインシステム」を生成します。

---

## BuilderOSで目指すべき次の段階

もしFramerを本気で超えるのであれば、AIが返すJSONは現在の数十項目では足りません。少なくとも以下のような構造まで拡張する必要があります。

```text
DesignDNA
├── Color Tokens
├── Typography Tokens
├── Spacing Scale
├── Radius Scale
├── Elevation
├── Grid System
├── Breakpoints
├── Motion Rules
├── Component Library
├── Layout Rules
├── Accessibility Rules
├── Brand Voice
└── Page Blueprints
```

そしてCanvasは、このDesignDNAを元にコンポーネントを組み立てるだけにします。

この構成になれば、

- Money Forwardを参考にすればMoney Forwardらしい情報設計・余白・コンポーネント構成になる
- Framerを参考にすればFramerらしいレイアウト思想になる
- Appleを参考にすればAppleらしいヒーロー構成やタイポグラフィになる

というように、**文章だけでなく、レイアウト・UI・デザインシステム全体が変わる**ようになります。

これはBuilderOSを「AIが文章を入れるページビルダー」から、「AIがデザインシステムを生成するビジュアルエディタ」へ進化させるための最も重要な設計変更です。memcite
