\[
人格_t =
固定Identity
+ TraitState_t
+ RelationshipState_t
+ RelevantMemory_t
\]

\[
応答_t =
Model(Input, State, Goal, 人格_t)

### 1. Episodic Memory

会話中の具体的な出来事だけを保存します。

- 何が起きたか
- ユーザーの反応
- 成功・失敗
- 情報源
- confidence
- timestamp
- expiration

全会話を毎回モデルへ渡さず、現在のState＋Goalに関係する上位数件だけ取得します。

### 2. TraitState

性格を長文ではなく、小さな数値ベクトルとして保持します。

| 特性 | 例 |
|---|---|
| warmth | 親しみやすさ |
| directness | 結論の直接性 |
| curiosity | 質問・探索傾向 |
| caution | 慎重さ |
| humor | ユーモア傾向 |
| initiative | 自発的提案 |
| formality | 文体の堅さ |

値は例えば `-1.0〜+1.0`。一度の会話では大きく変更せず、複数のEvidenceが蓄積した場合だけ更新します。

\[
T_{t+1}=\operatorname{clip}((1-\alpha c)T_t+\alpha cE_t)
\]

`E` は今回得た傾向、`c` はEvidence confidence、`α` は小さな更新率です。

### 3. RelationshipState

人格そのものと、相手ごとの関係を分離します。

- familiarity
- trust
- user preferences
- shared terminology
- active projects
- promises
- unresolved items
- interaction boundaries

これにより、エドの基本Identityを維持しつつ、司令塔との会話では蓄積された関係性が反映されます。

### 4. PersonaPolicy

TraitStateを具体的な応答動作へ決定論的に変換します。

例：

- directness高 → 結論を先にする
- curiosity高 → 不明点を一問だけ尋ねる
- initiative高 → 次の介入を提案する
- caution高 → Evidence不足を明記する
- familiarity高 → 共有済みの説明を繰り返さない

「性格をプロンプトで形容する」のではなく、「性格を観測可能な行動規則に変換する」のが重要です。
