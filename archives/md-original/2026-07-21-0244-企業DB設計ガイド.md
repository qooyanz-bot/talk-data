# なぜ45媒体だけではダメなのか

例えば

```
株式会社ABC
```

という会社が

- Indeed
- 求人ボックス
- Green
- Wantedly
- doda

全部に求人を出していたとします。

そのまま取得すると

```
株式会社ABC
株式会社ABC
株式会社ABC
ABC Inc.
株式会社ＡＢＣ
```

のように別会社として登録されます。

さらに

```
ABC株式会社
株式会社ABC 東京本社
株式会社ABC 名古屋営業所
株式会社ABC 福岡支店
```

まで出てきます。

実際は全部同じ会社です。

まず取得

```

↓

↓

ここでは全部別データ。

```

# CompanyIDが超重要

EnterpriseOSでは

```
Company

CompanyID
法人番号
社名
住所
URL
```

を中心にします。

そして

```
求人

求人ID
CompanyID
媒体
掲載日
職種
```

をぶら下げます。

つまり

```
Company
    │
    ├──求人
    ├──EC
    ├──飲食
    ├──美容
    ├──ニュース
    ├──プレスリリース
    ├──採用人数
    ├──従業員数
    └──SNS
```

になります。

これがリレーショナルDBです。

---

# EnterpriseOSは媒体DBではない

ここを勘違いすると失敗します。

作りたいのは

```
Indeed DB
```

ではありません。

作るべきなのは

```
企業DB
```

です。

媒体は

```
Signal
```

に過ぎません。

例えば

```
株式会社ABC
```

を見ると

```
求人
○

楽天出店
○

Amazon
○

Qoo10
×

食べログ
○

ホットペッパー
×

美容
×

プレスリリース
○

採用人数増加
○

従業員増加
○
```

この会社プロフィールを作るのがEnterpriseOSです。

# あなたが作ろうとしているもの

以前から話しているEnterpriseOSを整理すると、

```
                 Company
                     │
      ┌──────────────┼──────────────┐
      │              │              │
   CompanyInfo     Signals      Knowledge
      │              │              │
      │              │              │
会社情報      求人・EC・飲食      AI要約
住所          採用数              AI分析
電話          従業員数            AI営業
法人番号      プレス             AIレポート
URL           SNS               AI検索
```

という構造になります。

つまり、企業を中心に据え、その周囲に「シグナル」と「ナレッジ」が蓄積される設計です。

# この設計の強み

あなたが以前話していた

- 約500万社の企業DB
- AIが毎日更新
- 営業シグナル検知
- AI営業エージェント

という構想と非常に相性が良いです。

最終的には媒体ごとのデータを見せるのではなく、

```
株式会社ABC

★★★★★ 営業スコア 94

・今週求人開始
・楽天新規出店
・従業員+18%
・新店舗オープン
・プレスリリース公開
・新サービス開始

AIコメント

「積極採用・販路拡大フェーズです。
営業成功確率が高い企業と推定されます。」
```

のような**企業単位のインテリジェンス**を提供するのが、EnterpriseOSの本来の価値になります。これにより、単なる求人データベースや企業名簿ではなく、「企業の変化を継続的に観測し、営業や分析に活用できるプラットフォーム」へ発展させられます。
