この「**ビルド失敗対策**」で何をやっているのかを、処理の流れに沿って説明します。

## 1. sandboxIdから正しいSandboxへ再接続

Open-Lovableでは、サイトを再現するときにまずVercel Sandbox上でReactプロジェクトを生成します。

```
ユーザー
   ↓
Cloudflare Worker
   ↓
Vercel Sandbox
   ↓
Reactプロジェクト生成
```

Sandboxには

```
sandboxId = sbx_xxxxxxxxx
```

のようなIDがあります。

Cloudflare Workerはリクエストごとに新しいプロセスになるため、

```
前のリクエストで作ったSandbox
```

をメモリで保持できません。

そのため

```
sandboxId
```

から

```
Sandbox.get(...)
```

のようなAPIで再接続しています。

つまり

```
POST /deploy-generated-app
        ↓
sandboxId取得
        ↓
Vercel API
        ↓
同じSandboxへ再接続
```

という流れです。

---

## 2. 不足パッケージを自動インストール

AIは例えば

```jsx
import { motion } from "framer-motion"
```

を生成することがあります。

しかしpackage.jsonには

```
framer-motion
```

が入っていないことがあります。

その状態で

```
npm run build
```

すると

```
Cannot resolve module 'framer-motion'
```

となりビルドが失敗します。

そこで今回追加したのが

```
build失敗
    ↓
ログ解析
    ↓
不足ライブラリ抽出
    ↓
npm install
    ↓
build再実行
```

です。

例えば

```
Cannot find package
```

なら

```
npm install framer-motion
```

を自動実行します。

---

## 3. buildを再実行

インストール後

```
npm run build
```

をもう一度実行します。

成功すれば

```
dist/
```

が生成されます。

これがCloudflare Pagesへアップロードされます。

```
Sandbox

src/
package.json

↓

npm install

↓

npm run build

↓

dist/
```

---

## 4. Cloudflare Pagesへ公開

ビルド成功後は

```
dist
```

をそのままCloudflare Pages APIへ送ります。

```
dist
   ↓
Pages Direct Upload API
   ↓
https://xxxxx.pages.dev
```

このURLが画面に表示されます。

---

## 5. ビルド失敗時の詳細表示

以前は

```
Reactアプリの本番ビルドに失敗しました
```

だけでした。

原因が分かりませんでした。

今回の修正では例えば

```
Error

Cannot resolve module
framer-motion
```

や

```
vite.config.ts

Unexpected token
```

など、

実際のビルドログが表示されるようになります。

これにより

- importミス
- package不足
- JSXエラー
- TypeScriptエラー
- Vite設定エラー

など、失敗原因を直接確認できます。

## ただし、まだ限界があります

現在の実装で自動復旧できるのは主に**依存パッケージ不足**です。一方で、次のようなケースは自動では直りません。

- AIが文法的に壊れたReactコードを生成した
- コンポーネント間の参照関係が誤っている
- Vite設定そのものが壊れている
- TypeScriptの型エラーが多数ある
- React 19とライブラリのバージョン互換性がない

本当に「Lovable並み」の成功率を目指すなら、ビルド失敗後に単に`npm install`するだけでなく、

1. ビルドログをLLMに渡す
2. エラー内容を解析させる
3. コードを自動修正する
4. 再ビルドする
5. 成功するまで最大3〜5回繰り返す

という**自己修復（Self-Healing Build Pipeline）**を組み込むのが効果的です。これにより、単なる依存不足だけでなく、AI生成コード自体の不具合まで自動修正できるようになります。
