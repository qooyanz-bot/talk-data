「オーケストレーション」とは、**複数のエージェントやツールを、誰が・どの順序で・どの条件で実行するか制御すること**です。OpenAI Agents SDKでは、主に次の2方式があります。

1. **LLM主導**：GPT-5.6自身が担当エージェントを選ぶ  
2. **コード主導**：アプリケーション側で実行順序や並列処理を決める  

両者を組み合わせることもできます。citeturn908186view1

GPT-5.6では、`gpt-5.6`がGPT-5.6 Solを指すエイリアスとして提供され、Responses API、Function Calling、Structured Outputsなどを利用できます。citeturn908186view0turn908186view4

# パターン1：GPT-5.6に振り分けを任せる

最もシンプルなのは、受付役のエージェントに複数の専門家を登録し、GPT-5.6自身に担当を選ばせる方法です。

## 完成コード

```python
import asyncio

from agents import Agent, Runner


technical_agent = Agent(
    name="Technical Specialist",
    model="gpt-5.6",
    handoff_description=(
        "Python、API、クラウド、データベース、"
        "ソフトウェア設計などの技術的な質問を担当する"
    ),
    instructions="""
あなたはシニアソフトウェアエンジニアです。

以下の方針で回答してください。
- 実行可能なコードを提示する
- なぜその設計にするのか説明する
- セキュリティとエラー処理を考慮する
- 不明な情報を推測で断定しない
""",
)


business_agent = Agent(
    name="Business Specialist",
    model="gpt-5.6",
    handoff_description=(
        "事業企画、KPI、マーケティング、"
        "収益モデルなどのビジネス上の質問を担当する"
    ),
    instructions="""
あなたは事業開発コンサルタントです。

回答には次の内容を含めてください。
- 課題の整理
- 選択肢
- メリットとリスク
- 推奨アクション
""",
)


triage_agent = Agent(
    name="Triage Agent",
    model="gpt-5.6",
    instructions="""
ユーザーの依頼内容を分析し、適切な専門エージェントへ引き継いでください。

技術的な実装やシステム設計:
- Technical Specialist

事業戦略やKPI、マーケティング:
- Business Specialist

複数領域にまたがる場合は、中心的な課題を担当するエージェントを選んでください。
""",
    handoffs=[
        technical_agent,
        business_agent,
    ],
)


async def main() -> None:
    user_input = (
        "SaaSの解約率を分析するPython APIを設計してください。"
        "まずは技術構成を知りたいです。"
    )

    result = await Runner.run(
        triage_agent,
        user_input,
    )

    print("担当エージェント:", result.last_agent.name)
    print()
    print(result.final_output)


if __name__ == "__main__":
    asyncio.run(main())
```

実行します。

```bash
python main.py
```

## 仕組み

`handoffs`に専門エージェントを登録すると、GPT-5.6からは担当変更用のツールとして見えます。たとえば`Technical Specialist`への引き継ぎは、内部的には専門エージェントへ転送するツール呼び出しとして扱われます。citeturn908186view2

この方式は、次の用途に向いています。

- カスタマーサポートの問い合わせ分類
- 技術、営業、法務などへの振り分け
- ユーザーの依頼内容が事前に確定できないサービス
- 会話の自然さを重視するアプリケーション

一方、厳密な実行順序が必要な業務では、次のコード主導方式が適しています。

# パターン2：複数エージェントを並列実行して統合する

調査、レビュー、分析など、複数の視点を集めたい場合は、アプリケーション側で各エージェントを並列実行し、最後に統合エージェントへ渡します。

```python
import asyncio
from dataclasses import dataclass

from agents import Agent, Runner


research_agent = Agent(
    name="Research Agent",
    model="gpt-5.6",
    instructions="""
あなたは技術調査担当です。
与えられたテーマについて、技術的な選択肢、前提条件、
導入上の注意点を整理してください。
""",
)


architecture_agent = Agent(
    name="Architecture Agent",
    model="gpt-5.6",
    instructions="""
あなたはソフトウェアアーキテクトです。
スケーラビリティ、可用性、保守性、セキュリティの観点から
システム構成を提案してください。
""",
)


risk_agent = Agent(
    name="Risk Agent",
    model="gpt-5.6",
    instructions="""
あなたはリスクレビュー担当です。
技術リスク、運用リスク、コスト、障害時の影響、
セキュリティ上の注意点を厳しく指摘してください。
""",
)


editor_agent = Agent(
    name="Lead Editor",
    model="gpt-5.6",
    instructions="""
あなたはリードアーキテクトです。

複数の専門家による分析を統合し、次の構成で日本語の提案書を作成してください。

1. 推奨構成
2. 採用理由
3. システム構成
4. 実装ステップ
5. リスクと対策
6. 最初に作るべき最小構成

専門家同士の意見が食い違う場合は、論点を示したうえで判断してください。
""",
)


@dataclass
class ExpertReport:
    name: str
    content: str


async def run_expert(
    agent: Agent,
    task: str,
) -> ExpertReport:
    result = await Runner.run(agent, task)

    return ExpertReport(
        name=agent.name,
        content=str(result.final_output),
    )


async def main() -> None:
    task = """
社内文書を検索して回答するRAGシステムを設計してください。

条件:
- 利用者は500人
- PDFと社内Wikiを検索対象にする
- アクセス権限を回答に反映する
- Pythonで実装する
- 将来的に複数部署へ展開する
"""

    # 3人の専門家を並列実行
    reports = await asyncio.gather(
        run_expert(research_agent, task),
        run_expert(architecture_agent, task),
        run_expert(risk_agent, task),
    )

    combined_reports = "\n\n".join(
        f"## {report.name}\n{report.content}"
        for report in reports
    )

    synthesis_prompt = f"""
以下は、同じ案件について3人の専門家が作成した分析です。

# 元の依頼

{task}

# 専門家の分析

{combined_reports}

これらを統合し、実行可能な最終提案を作成してください。
"""

    final_result = await Runner.run(
        editor_agent,
        synthesis_prompt,
    )

    print(final_result.final_output)


if __name__ == "__main__":
    asyncio.run(main())
```

## この方式の利点

専門家同士に依存関係がなければ、`asyncio.gather()`で同時に動かせます。

```text
ユーザーの依頼
      │
      ├── 技術調査エージェント ──┐
      ├── 設計エージェント ──────┼── 統合エージェント
      └── リスクエージェント ────┘
```

LLMにすべて任せるのではなく、アプリケーション側で次を保証できます。

- 必ず3種類のレビューを実行する
- 並列処理によって待ち時間を短縮する
- 一部の結果だけを再実行する
- タイムアウトやリトライを個別に設定する
- 実行結果を監査ログへ残す

# パターン3：エージェントをツールとして使う

「担当そのものを引き継ぐ」のではなく、管理エージェントが専門家へ一時的に問い合わせ、最後まで回答責任を持つ構成もあります。

Agents SDKは、別のエージェントを呼び出し可能なツールとして公開できます。これはハンドオフとは異なり、管理エージェントが会話の主導権を維持するパターンです。citeturn908186view5

```python
import asyncio

from agents import Agent, Runner


security_agent = Agent(
    name="Security Reviewer",
    model="gpt-5.6",
    instructions="""
コードやシステム設計をセキュリティ観点でレビューしてください。
脆弱性、認証・認可、秘密情報、入力検証、監査ログを確認してください。
""",
)


performance_agent = Agent(
    name="Performance Reviewer",
    model="gpt-5.6",
    instructions="""
コードやシステム設計を性能観点でレビューしてください。
計算量、I/O、並列処理、キャッシュ、ボトルネックを確認してください。
""",
)


manager_agent = Agent(
    name="Engineering Manager",
    model="gpt-5.6",
    instructions="""
あなたはエンジニアリングマネージャーです。

ユーザーから設計やコードを受け取り、必要に応じて専門家ツールを呼び出してください。
専門家の結果をそのまま並べるのではなく、重複を除去して優先順位を付け、
最終的な改善案としてまとめてください。
""",
    tools=[
        security_agent.as_tool(
            tool_name="review_security",
            tool_description="設計やコードのセキュリティレビューを行う",
        ),
        performance_agent.as_tool(
            tool_name="review_performance",
            tool_description="設計やコードの性能レビューを行う",
        ),
    ],
)


async def main() -> None:
    request = """
次のAPI設計をレビューしてください。

- FastAPIで注文登録APIを作る
- 注文をPostgreSQLへ保存する
- 保存後に決済APIを同期的に呼び出す
- 成功したらメールを送信する
- リトライ処理はまだない
"""

    result = await Runner.run(
        manager_agent,
        request,
    )

    print(result.final_output)


if __name__ == "__main__":
    asyncio.run(main())
```

## ハンドオフとの違い

| 方式 | 最終的に回答する担当 | 適した用途 |
|---|---|---|
| ハンドオフ | 引き継ぎ先のエージェント | 問い合わせ分類、専門窓口 |
| Agent as Tool | 管理エージェント | 複数専門家の意見を統合 |
| コード主導 | コードで指定したエージェント | 固定ワークフロー、監査対象業務 |

# Function Toolを組み込む

エージェントには、自社APIやデータベース処理をPython関数として渡せます。Agents SDKでは、Python関数をFunction Calling用ツールとしてラップできます。citeturn908186view5

```python
import asyncio
from datetime import datetime, timezone

from agents import Agent, Runner, function_tool


CUSTOMERS = {
    "C001": {
        "name": "株式会社サンプル",
        "plan": "Enterprise",
        "status": "active",
    },
    "C002": {
        "name": "テスト商事",
        "plan": "Standard",
        "status": "suspended",
    },
}


@function_tool
def get_customer(customer_id: str) -> dict:
    """顧客IDから顧客情報を取得する。"""
    customer = CUSTOMERS.get(customer_id)

    if customer is None:
        return {
            "found": False,
            "customer_id": customer_id,
        }

    return {
        "found": True,
        "customer_id": customer_id,
        **customer,
    }


@function_tool
def create_support_ticket(
    customer_id: str,
    title: str,
    priority: str,
) -> dict:
    """サポートチケットを登録する。"""
    allowed_priorities = {"low", "medium", "high"}

    if priority not in allowed_priorities:
        return {
            "success": False,
            "error": "priority must be low, medium, or high",
        }

    return {
        "success": True,
        "ticket_id": "TICKET-1001",
        "customer_id": customer_id,
        "title": title,
        "priority": priority,
        "created_at": datetime.now(timezone.utc).isoformat(),
    }


support_agent = Agent(
    name="Support Agent",
    model="gpt-5.6",
    instructions="""
あなたは法人向けサービスのサポート担当です。

最初に顧客情報を確認してください。
障害や利用不能に関する問い合わせでは、必要に応じて
サポートチケットを作成してください。

チケットを作成した場合は、チケットIDを必ず案内してください。
""",
    tools=[
        get_customer,
        create_support_ticket,
    ],
)


async def main() -> None:
    result = await Runner.run(
        support_agent,
        "顧客ID C001です。管理画面へログインできません。緊急で確認してください。",
    )

    print(result.final_output)


if __name__ == "__main__":
    asyncio.run(main())
```

本番環境では、更新系ツールに次の仕組みを追加してください。

- ユーザー認証と権限確認
- 入力値検証
- タイムアウト
- リトライと冪等性キー
- 実行前の承認
- 監査ログ
- ツールが返すデータ量の制限

# 実運用向けの選び方

最初は、次の基準で選ぶと分かりやすいです。

```text
依頼内容によって担当が変わる
        ↓
ハンドオフ

管理者が専門家の意見を集めたい
        ↓
Agent as Tool

処理順序が業務ルールで決まっている
        ↓
コード主導

独立した調査を複数実行したい
        ↓
コード主導＋並列実行
```

特に、金銭処理、データ削除、外部公開、契約変更のような操作は、LLMの自律判断だけに任せず、コード側で承認条件を制御する設計が安全です。
