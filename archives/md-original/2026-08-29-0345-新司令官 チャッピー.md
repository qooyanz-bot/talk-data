## グランドデザインの核心

時間速度の異なる5つのループを分離します。

1. **反射・安全ループ**
   - 衝突回避、関節制限、停止、非常停止
   - 決定論的な制御系
   - LLMから完全に独立

2. **知覚ループ**
   - カメラ、音声、身体状態を連続処理
   - 映像や音声を全部保存せず、必要なExperience Eventへ変換

3. **認知ループ**
   - Canonical State、GoalContract、Identity、Relationshipを統合
   - Planner、Binding、Executor、Recoveryを実行
   - 解けない残差だけFrontierモデルへ送る

4. **記憶ループ**
   - Raw Experienceは追記型
   - Concept、Relation、TraitはRawへの参照を持つ派生Index
   - 次の式で必要な記憶だけ取得する

   `State + Goal + Identity + Relationship + Concept → Memory Address`

5. **監査・学習ループ**
   - replay、hash、cost、failure、correctionを保存
   - 人格・モデル・ルールの更新はオンラインで勝手に行わず、検証後に昇格

ROS側でも「低遅延」と「締切を保証する決定論的リアルタイム」は別物とされています。[ROS 2 Real-time Design](https://design.ros2.org/articles/realtime_background.html)  
また、MoveItのHybrid Planningも、遅いGlobal Plannerと高速・決定論的なLocal Plannerを分離しています。[MoveIt Hybrid Planning](https://moveit.picknik.ai/main/doc/concepts/hybrid_planning/hybrid_planning.html)

## 開発ロードマップ

| 段階 | 作るもの | 合格条件 |
|---|---|---|
| 0. Integrity | Prototypeのcommit lineage修復、EPI Interface Freeze | commit・branch・schema・replayが一致 |
| 1. Chappy Brain | テキスト会話、永続記憶、関係性、Local/Frontier routing | 再起動後も出典付きで記憶を再取得 |
| 2. Eyes & Ears | iPhone/PCの映像・音声を受動的に理解 | 発話者・物体・出来事を時系列Event化。物理操作は禁止 |
| 3. Virtual Body | ROS 2シミュレーター上の身体 | 全ActionIntentがGuard、simulation、auditを通過 |
| 4. Small Body | 首振りカメラ、小型移動台など限定身体 | 独立非常停止、速度制限、通信断時停止 |
| 5. Humanoid Adapter | 市販人型ロボットへの接続 | 身体固有機能をAdapter化し、EPI本体を変更しない |

Phase 0〜3は、既存PC・iPhone・シミュレーターとOSS中心で、ロボット購入前に進められます。ローカル推論はLLM/VLMとAPIサーバーを持つ [llama.cpp](https://github.com/ggml-org/llama.cpp)、音声試作はリアルタイム入力例がある [whisper.cpp](https://github.com/ggml-org/whisper.cpp) が低コスト候補です。
