# AIアシスタントを使い分ける時代に、スキル管理はもっと楽でいい

AIコーディングアシスタントは、もはや単なる補助ツールではなくなりつつあります。

コードを書かせる。  
レビューを頼む。  
設計を相談する。  
テストケースを考えさせる。  
ドキュメントを整理する。

開発者にとって、AIは作業の一部になりつつあります。

ただ、AIツールが増えるほど、別の問題も見えてきます。  
それが「設定」や「スキル」の分散です。

Claude Codeではこのスキルを使っている。  
Codexでは別の場所に似たようなプロンプトがある。  
Opencode用には、少し書き方を変えたファイルを置いている。

最初はそれでも問題ありません。  
でも、少しずつ運用していくうちに、管理はだんだん複雑になります。

「このスキル、どこに置いたっけ？」  
「Claude Code側だけ古いままだった」  
「同じ内容を3つのフォルダにコピーしている」  
「消していいファイルなのか、リンクなのかわからない」

こうした小さなストレスは、ひとつひとつは大したことがありません。  
けれど積み重なると、集中力を削ります。

本来、開発者が考えたいのは、もっと本質的なことのはずです。  
どう設計するか。  
どう品質を上げるか。  
どうAIをチームや自分のワークフローに自然に組み込むか。

スキルファイルの置き場所で迷う時間は、できるだけ少ないほうがいい。

Skills Managerは、まさにそのためのデスクトップアプリケーションです。

# Skills Managerとは何か

Skills Managerは、AIコーディングアシスタント向けのスキルを一元管理するためのアプリです。

対応しているツールは、Claude Code、Codex、Opencodeなど。  
これらのツールで使うスキルを、ひとつの場所にまとめて整理し、必要なツールへ同期できます。

ポイントは、単にファイルをコピーするのではなく、**シンボリックリンク**を使って同期することです。

つまり、スキルの本体は中央の管理フォルダに置かれます。  
各AIツール側には、その本体を参照するリンクが作られます。

これにより、同じファイルをあちこちに複製する必要がありません。

一度スキルを作成すれば、対応するAIツール全体で利用できます。  
内容を更新すれば、その更新はリンク先にも反映されます。

「どれが最新版なのか」を気にする必要が減る。  
「コピーし忘れた」というミスも減る。  
管理の中心がひとつになる。

この考え方は、複数のAIツールを使う人ほど効果を感じやすいはずです。

Skills Managerの大きな特徴は、統合管理です。

AIツールごとにバラバラだったスキルを、ひとつの安全な場所に集められます。

たとえば、コードレビュー用のスキル。  
コミットメッセージ生成用のスキル。  
リファクタリング方針を相談するスキル。  
ドキュメント作成を補助するスキル。

こうしたスキルを、自分の作業スタイルに合わせて育てていく人は少なくありません。

AIをうまく使う人ほど、単発のプロンプトではなく、再利用できる型を持っています。  
何度も使う指示は、スキルとして整えておいたほうが効率的です。

ただ、その「育てたスキル」が複数のツールに散らばっていると、せっかくの資産が扱いにくくなります。

Skills Managerは、スキルを資産として扱いやすくします。

ひとつの場所で見渡せる。  
必要なものを整理できる。  
ツールごとの状態も確認しやすい。

これは地味ですが、日常的に使う道具としてはとても重要です。

# コピーではなく、リンクで同期する

Skills Managerの核にあるのは、スマート同期です。

自動的にシンボリックリンクを管理し、各ツールが常に最新バージョンのスキルを参照できるようにします。

ファイルをコピーして同期する方式には、わかりやすさがあります。  
しかし、コピーは増えるほど管理が難しくなります。

同じ名前のファイルが複数ある。  
片方だけ修正されている。  
どちらを残すべきかわからない。  
古いファイルを誤って使い続ける。

スキルのように、少しずつ改善していくものほど、この問題は起きやすくなります。

一方、シンボリックリンクを使えば、ファイルの本体はひとつです。  
各ツールは、その本体を参照します。

だから、更新する場所もひとつ。  
管理する基準もひとつ。

スキルを増やしていくほど、この差は大きくなります。

# ツールごとに有効・無効を切り替えられる

すべてのスキルを、すべてのツールで使いたいとは限りません。

Claude Codeでは使いたいけれど、Codexでは使わない。  
Opencodeでは試したいけれど、他の環境にはまだ入れたくない。

そんな場面もあります。

Skills Managerでは、元のファイルを削除せずに、個々のツールに対してスキルを有効化・無効化できます。

これはとても実用的です。

スキルそのものは残しておきたい。  
でも、今は特定のツールでは使いたくない。  
試験的に導入して、うまくいけば他のツールにも広げたい。

そうした運用がしやすくなります。

AIツールの使い方は、人によってかなり違います。  
ひとつの正解があるというより、作業内容や開発スタイルに合わせて調整していくものです。

だからこそ、細かく制御できることには意味があります。

Skills Managerは、macOS、Windows、Linuxに対応しています。

# Windowsでは管理者権限が必要になる場合がある

ひとつ注意したいのは、Windows環境でのシンボリックリンク作成です。

Windowsでは、開発者モードが有効になっていない場合、シンボリックリンクを作成するために管理者権限が必要になることがあります。

スキルの同期時に権限エラーが出る。  
リンクの作成に失敗する。  
ツールの検出がうまくいかない。

こうした場合は、アプリケーションを管理者として実行すると解決する可能性があります。

Skills Managerはシンボリックリンクを活用するアプリなので、この点は事前に知っておくと安心です。

---

# Linuxで真っ白な画面が出る場合

Linux環境、とくにVMwareやVirtualBoxのような仮想マシン上でAppImageを起動したとき、画面が真っ白になることがあります。

これは、WebKitGTKのハードウェアアクセラレーションに関係する問題である可能性があります。

その場合は、以下のように環境変数を指定してターミナルから起動します。

```bash
WEBKIT_DISABLE_COMPOSITING_MODE=1 ./Skills-Manager_1.0.1_amd64.AppImage
```

デスクトップアプリをクロスプラットフォームで提供する場合、環境ごとの相性問題は避けにくい部分があります。  
こうしたトラブルシューティングが明記されているのは、実際に使う側にとってありがたいところです。
