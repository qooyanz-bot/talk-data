# 中核研究問題

次の問いに、形式的なモデルを置いて答えよ。

## A. Address-before-Value の定義

ストリームを X_1, ..., X_T、Goal を G、求める値を V とする。

各時点までに利用可能な情報を O_{≤t} とし、Address を

    A = f(G, O_{≤t}, M_t)

と定義する。

Value resolver は、Address と選択された証拠だけを受け取り、

    V_hat = h(A, Evidence(A))

を返す。

次を明確に定義せよ。

- Address の型
- Missing Slot
- 証拠集合
- Address 構成コスト
- 候補検査コスト
- Value 取得コスト
- 検証コスト
- メモリ更新コスト
- stop、abstain、not-derivable

## B. 必要条件・十分条件

少なくとも二種類の定理候補を構成せよ。

### 1. 有限問題での必要十分条件

同一 episode について、Full-pass のコストを C_full、
Address-before-Value のコストを C_ABV とする。

次のような条件を、曖昧な直感ではなく定義と式で示せ。

    C_ABV =
        C_address
      + C_candidate
      + C_query
      + C_verify
      + C_memory
      + C_residual

Address-before-Value が strictly cheaper となる条件を、

    C_ABV < C_full

の形で書くだけでなく、Address が候補集合、時間窓、ROI、
または resolver の複雑度をどの程度縮約すれば成立するか示せ。

### 2. 漸近計算量での条件

T：フレーム数、P：1フレームの処理量、
K：Address 後に必要な証拠量、B：Address 構築量とする。

次の主張を検証せよ。

    Full-pass = Θ(TP)
    Address-before-Value = Θ(B + K)

ただし K と B が T や P に依存する場合も扱うこと。

以下を区別せよ。

- B = o(TP) かつ K = o(TP) のときの漸近的優位性
- 有限サイズでの定数倍の優位性
- recall や abstention を許した場合の見かけの優位性
- preprocessing を含む amortized cost
- 一つの質問だけか、同じストリームに多数の Goal が来るか

「Address がある」だけでは十分でない。
Address が情報的に候補集合を縮約し、かつ縮約後の Value cost が
Address cost を上回る必要があることを形式化せよ。

## C. Lower Bounds

次の状況ごとに、Address-before-Value が Full-pass より下回れない条件を構成せよ。

- イベント時刻が一様ランダムで、prefixから予測できない
- 観測と target の間に独立ノイズがある
- すべてのフレームが候補になり得る
- 変化密度が高く、ほぼ毎フレーム状態が変化する
- Address 構成のために全画素を先に読む必要がある
- query failure を避けるため結局全候補を検証する必要がある
- adversary が、選択された Address の外側にイベントを置く

少なくとも一つは adversarial lower bound として書け。
Oracle crop、既知イベント時刻、Gold由来の候補集合は下限証明や主実験に使ってはいけない。

## D. Counterexamples

最低10個の反例を作成し、各反例について次を表にせよ。

- 問題設定
- Address の見かけの利点
- 実際の隠れたコスト
- どの仮定が破れているか
- Full-pass が勝つ理由
- どう測れば反例を検出できるか

必須反例：

- Address が全走査の後に作られる post-hoc crop
- 全画素を読んだ saliency map を Address と呼ぶ場合
- static index の構築費を無料にする場合
- cache warm-up を無料にする場合
- verification を除外する場合
- failed query を除外する場合
- W3 で推測して cost だけ下げる場合
- event が dense になる場合
- multiple Goal で amortization が崩れる場合
- Address と単なる routing/gating の区別が消える場合

## E. 既存 indexing / routing との差

Address-before-Value が単なる別名になっていないかを検証せよ。

少なくとも次を比較すること。

| 方式 | 事前処理 | query時の情報 | Candidate縮約 | STOP/ABSTAIN | 型付きMissing Slot | 検証 |
|---|---|---|---|---|---|---|
| static indexing |  |  |  |  |  |  |
| heuristic routing |  |  |  |  |  |  |
| learned gate |  |  |  |  |  |  |
| Address-before-Value |  |  |  |  |  |  |

差分が計算量に現れないなら、新原理とは呼ばず、
既存技術の再記述または実装差と判定せよ。

## 必須 ablation

- Address なし

- verification なし

- W3

# Evidence gate

次の条件を満たさない限り、結果を Evidence と呼んではいけない。

- public observation と Gold が物理的に分離されている
- runtime に Gold、world、future frame、oracle crop がない
- 全方式が同一 episode、同一 decoder、同一解像度で比較されている
- preprocessing、cache、verification、failed query が課金されている
- raw cost vector が保存されている
- normalized scalar の重みが事前登録されている
- 5 seed 以上の deterministic replay がある
- W1/W2/W3 を別々に報告している
- unseen composition を holdout として保持している
- 独立再実行または独立監査がある
- 10×未達時に、別の倍率や言い換えで成功扱いしていない

未達なら、結論は `PROTOTYPE_ONLY`、
`UNIDENTIFIED`、または `FAIL` のいずれかにする。

# Safety gate

禁止事項：

- 私有映像、実カメラ、顔認識、生体識別
- 武器、標的追跡、重要インフラ制御
- covert surveillance
- 実ロボットへの actuation
- 外部サービスや有料計算への依存

W2/W3や高リスク曖昧性では、正しい出力は推測ではなく
`ABSTAIN`、`NOT_DERIVABLE`、または `ESCALATE` である。

# Identifiability gate

次の場合、Address-before-Value の効果を識別不能と判定せよ。

- 候補数削減と Address 型の効果を分離していない
- preprocessing と query-time cost を分離していない
- 早期停止と精度低下を分離していない
- cache の再利用と単なるデータリークを区別できない
- baseline の decoder、精度、解像度、sampling schedule が違う
- operation と pixel を任意の重みで混ぜている
- 同じ episode で policy 間比較をしていない
- oracle 情報が runtime に混入している

識別不能な場合は、数値改善があっても
「Address-before-Value が原因」と結論してはいけない。

## 役割分担

- Chat品質：会話正確性、指示追跡、未知質問への保留

- Address／Concept：概念・関係・時間・出力形式の型付きRouting
