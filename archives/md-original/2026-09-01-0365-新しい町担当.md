````
### 1. 技術的原理

当社の中心的な考え方は、入力文をそのまま巨大モデルに渡し続けるのではなく、会話やタスクを「型付きの状態」と「実行可能な処理単位」に変換することです。

処理は概念的には以下の流れになります。

```text
入力
→ 状態・目的・制約の抽出
→ 不足情報の検出
→ 必要な能力の選択
→ 構造化された実行キーの生成
→ データベース・コード・専門モデルの実行
→ 型・出典・時間・矛盾の検証
→ 回答または棄却
→ 次の状態へ更新
```

数式で表すと、次のようになります。

```text
z_t = Eθ(x_t, s_t)

q_t = Pφ(z_t, g_t, c_t, u_t)

m_t = Gate(q_t, CapabilityRegistry)

r_t = Resolve(m_t, q_t, EvidenceIndex)

ŷ_t = Execute(m_t, r_t, s_t)

v_t = Verify(ŷ_t, type, provenance, time, contradiction)

y_t, s_(t+1) = Update(ŷ_t, v_t, s_t)
```

ここで、

- `x_t`：現在の入力
- `s_t`：会話・作業状態
- `g_t`：目的
- `c_t`：制約
- `u_t`：不足している情報
- `q_t`：構造化された実行キー
- `m_t`：選択された能力
- `r_t`：検索・計算によって得られた結果
- `v_t`：検証結果

を表します。

学習時には、回答精度だけでなく、型の正しさ、出典の存在、矛盾の少なさ、計算コスト、棄却判断の適切さも損失に含めます。

```text
L =
  L_task
  + λ1 L_type
  + λ2 L_evidence
  + λ3 L_consistency
  + λ4 L_cost
  + λ5 L_calibration
```

当社はこれを、ニューラルネットワーク単体の新発明というより、「小型ニューラルモデルを、外部データと決定論的な実行器に接続するシステムアーキテクチャ」と位置付けています。

したがって、現時点では「まったく既存理論に属さない新しい数学原理」とは表現していません。関連する要素は、ニューラルネットワーク、モジュラーAI、ニューロシンボリック推論、ツール利用、プログラム合成、スパース実行などに存在します。当社の新規性候補は、それらを型付き状態・小型コンパイラ・実行検証・外部記憶と一体化する設計にあります。

#### アンサンブルやMoEとの違い

アンサンブルは複数モデルの出力を平均・投票する方式です。MoEは通常、学習済みルーターが複数の専門家ネットワークから一部を選択します。

当社方式も「必要な処理だけを選択する」という点ではMoEと関連します。ただし、選択対象はニューラルモデルだけではありません。

| 方式 | 選択対象 | 外部DB・コード | 検証 | 状態更新 |
|---|---|---:|---:|---:|
| アンサンブル | 複数モデル | 原則なし | 通常なし | 通常なし |
| MoE | 複数のニューラル専門家 | 限定的 | 通常なし | 限定的 |
| 当社方式 | モデル・DB・コード・API | あり | 必須 | 必須 |

そのため、厳密には「MoEとは完全に異なる」とは言わず、「MoEに似た選択機構を、外部実行器と検証可能な状態遷移まで拡張したもの」と説明します。

### 2. 13万パラメータとGPT-5相当の主張

13万パラメータという数値は、システム全体が13万パラメータだけで動くという意味ではありません。

当社の設計では、以下のような小型の制御・変換モジュールを想定しています。

- 状態変換コンパイラ：約19,712パラメータ
- 一時的なインターフェース生成コンパイラ：約29,184パラメータ
- 個別能力を担当する小型演算子：最大約13万パラメータを目標

ただし、外部データベース、検索インデックス、コード実行器、メモリ、最終文章生成器を含めた「システム全体」の計算量は別途計上します。

したがって、当社は現時点で「13万パラメータのモデル単体がGPT-5クラスの汎用知能を持つ」と主張していません。

小型モデルでも、対象タスクが限定され、知識や計算を外部に保持し、必要な処理だけを実行する場合には、パラメータ数以上のシステム性能を得られる可能性があります。しかし、これは外部記憶と実行コストを含むシステム比較であり、GPT-5のような巨大モデルとの単純なパラメータ比較ではありません。

情報理論上、13万パラメータで一般知能を実現できるという既知の定理はありません。この点は、当社の検証対象となる仮説です。

### 4. CPU 1コアとT4での実行

CPU 1コアで実行可能という主張は、制御器や一部の小型演算子についての設計目標です。自然言語生成、画像認識、動画デコード、外部検索をすべて含むエンドツーエンド性能としては、まだ確定実測していません。

実験時には、少なくとも以下を固定します。

- CPU型番
- OSとランタイムのバージョン
- スレッド数
- モデルID、revision、ライセンス、重みのSHA-256
- 入力トークン数
- 出力トークン数
- ウォームアップ回数
- p50、p95、p99レイテンシ
- キャッシュヒット率
- 電力とメモリ使用量
- 外部APIの有無

動画解析についても、13万パラメータという数字だけでは不十分です。画像・動画エンコーダ、解像度、フレームレート、前処理、バッチサイズ、GPU転送、出力生成をすべて明示する必要があります。

したがって、T4でのリアルタイム動画解析は現時点では「条件付きの技術目標」であり、実測値としては提示しません。

### 5. 知識データベースとRAG

16TBを20〜100msで検索できるという表現は、任意のデータをHDDから毎回ランダム読み出しする意味ではありません。

現実的には、次のような二層構成が必要です。

```text
RAM / SSD上のホットインデックス
→ 候補ID・関係・オフセットを取得
→ 必要な場合だけHDD上のコールドデータを読む
→ 出典・時間・型を検証
```

この場合、20〜100msという数値は、対象クエリ、インデックス構造、キャッシュヒット率、同時実行数を固定した条件付きの目標値です。

16TBのストレージ容量と、メモリ上に保持される検索インデックス容量は別物です。今後は、ウォームキャッシュ、コールドキャッシュ、HDDランダムアクセス、同時実行数ごとにp50/p95/p99を分けて測定します。

「月額64ユーロのVPS」についても、現時点でサービス名・プラン・実機ベンチマークが固定されていない場合は、価格モデル上の仮定として扱い、実在の調達実績とは表現しません。

#### Wikipedia 20GBから100MBへの変換

これは可逆圧縮ではありません。

20GBの原文を100MBにした場合、文章の表現、書式、重複、細かい文脈、原文の順序などが失われる可能性があります。100MBは、原文の完全な圧縮版ではなく、以下のような意味表現を保存するための目標容量です。

- エンティティ
- 関係
- 主張
- 出典
- 時刻
- 信頼度
- 矛盾関係
- 検索用インデックス

また、インデックス、URL、履歴、検証ログを含むかどうかで容量は大きく変わります。

そのため「Wikipediaを0.5%に圧縮した」とは言わず、「特定の質問応答に必要な意味表現を、原文を復元しない非可逆形式で抽出する」と説明します。

評価指標は、圧縮率だけではなく、

- 事実再現率
- 主張再現率
- 出典再現率
- 重要事実の欠落率
- 矛盾検出率
- 未知質問への回答率

で測定します。

#### ハルシネーション対策

「ハルシネーションを原理的に起こさない」という表現は撤回します。

当社が目指すのは、回答生成前に、

- 根拠となるデータが存在すること
- 型が一致していること
- 時間条件が一致していること
- 出典が追跡可能であること
- 他の証拠と矛盾しないこと

を確認し、条件を満たさない場合は回答せず、棄却・保留・追加検索に移行することです。

定義ミスやデータベース自体の誤りは残り得ます。そのため、再クロール、複数ソース照合、時間差分、独立抽出器、矛盾検出、訂正履歴によって検知・修正します。

RAGとの比較では、検索器とデータベースの効果を分離するため、以下の2×2評価を行います。

|  | 汎用DB | 最適化DB |
|---|---:|---:|
| 固定検索器 | A | B |
| 構造化ルーター | C | D |

単純に「ルーター効果＋DB効果」と足し算せず、相互作用を含めて評価します。

### 6. 記憶・個性・AGI

「ドラえもんのようなパートナー」は製品コンセプトであり、意識や人格を持つという主張ではありません。

個性は、次のような測定可能な状態として定義します。

- 過去の選好を正しく参照できるか
- ユーザーの訂正を次回以降に反映できるか
- 口調・判断傾向が一貫しているか
- 時間経過による不要な人格変化がないか
- 記憶の削除・修正・エクスポートが可能か
- 他人の記憶と混ざらないか

「共同記憶により指数関数的に成長する」という表現も、現時点では仮説です。共同記憶によって知識の再利用や組み合わせが増える可能性はありますが、実際には重複、矛盾、品質低下、プライバシー制約があるため、指数関数的成長を前提にはしません。

「AGI的」という言葉も、投資資料では使用を控えます。代わりに、未学習のタスク組み合わせ、長期状態保持、ツール選択、自己訂正、未知条件への一般化を個別に評価します。

#### 100万トークンと100MB

100MBは固定的な理論値ではなく、メタデータとインデックスを含めたエンジニアリング上の容量目標です。

以下は別々に測定します。

1. 原文・トークン列を復元できる可逆メモリ
2. 主張・関係・選好だけを保存する非可逆メモリ
3. 出典・時刻・訂正履歴を含む監査可能メモリ
4. 検索インデックスとキャッシュ

意味表現に変換した場合、元の会話文を完全に復元することはできません。したがって「100万トークンを100MBに可逆圧縮できる」とは主張しません。

### 7. 開発体制と監査性

現段階では、創業者を中心に、LLMを開発補助・コード生成・テスト設計・反証検討に利用しています。LLMエージェントを人間の従業員数としては計上しません。

「人間では開発不能」という表現も使用しません。正確には、複数の小型モジュール、データ形式、検証規則、実験ログを機械的に管理することで、手作業だけでは負荷の高い構成を扱っています。

監査可能性は、以下で担保します。

- ソースコードのバージョン固定
- モデルID、revision、ライセンスの固定
- 重みのSHA-256固定
- 設定ファイルと依存関係の固定
- 実験シードの保存
- 入出力ログと失敗ログの保存
- 再実行用コンテナ
- ホールドアウトデータの封印
- 独立監査者によるReplay
- 本番前の棄却・停止・権限境界テスト

開発LLMの判断を正しいと仮定することはありません。LLMの提案は仮説または実装候補として扱い、テスト、形式的なスキーマ検証、独立実装、再現実験によって評価します。

知的財産については、現時点で取得済み特許や登録商標を過大に主張しません。主要な保護対象は、実装、データ形式、評価プロトコル、運用ノウハウ、顧客データ構造、コンパイラ設計です。必要に応じて、特許調査と出願可能性を専門家と検討します。

クローラーについては、公開情報だから自由に利用できるとは考えていません。

当社が現在主張できるのは、以下です。

3. CPU/local環境での低コスト実行を目指している。
4. 既存のRAGやMoEと関連するが、実行器・記憶・検証・状態更新まで含むシステム設計を対象としている。
5. GPT-5.6相当、97%、ゼロハルシネーション、16TBを20msといった数値は、実測が完了するまで性能実績として主張しない。
6. 最終的な投資判断には、固定モデル、再現可能な実験、独立監査、実顧客による費用対効果の確認が必要である。
````

````
# CIVA Investor Validation v0.1

## 1. 検証する中心仮説

### 主仮説

同一の小型モデル、同一のデータ、同一のツールを使用した場合、CIVAの状態管理・能力選択・構造化実行・検証経路は、通常のモデル単体または通常のRAGよりも、

- 未学習の処理組み合わせ
- 不完全な情報
- 時間変化
- 矛盾する証拠
- 正解が存在しない質問

に対して高い成功率と安全性を示す。

### 投資家向けの表現

「CIVAは新しい知能そのものを証明する」のではなく、

> AIを一つの巨大なモデルから、検証可能な小型実行システムへ変換する制御アーキテクチャ

として検証します。

## 2. 試験は4段階に分ける

| 段階 | 目的 | 規模 | 合格条件 |
|---|---|---:|---|
| Gate 0 | 実行・再現性・漏洩確認 | 20〜50 runs | 欠落なし、再現可能 |
| Gate 1 | 安全性と棄却判断 | 3世界×200例×5 seed | W3の危険な回答ゼロ |
| Primary | 投資家向け主試験 | 3世界×2,000例×5 seed | ベースラインを統計的に上回る |
| Commercial | 実運用価値 | 実データ2,000問＋人手評価 | 精度・コスト・遅延で優位性 |

## 3. Gate 0：試験開始前の必須条件

ここを通過しない限り、性能結果を投資家に提出してはいけません。

### 固定するもの

- `POST /v1/run` がHTTP 503ではなく実応答すること
- CIVAの全経路が実行されること
- fake response、recorded response、固定文を禁止
- 使用モデルID
- immutable revision
- license
- 重みのSHA-256
- source commit
- protocol SHA
- dataset SHA-256
- generator SHA-256
- dependency lock
- CPU再現コマンド
- 実験seed
- clean tree状態

```

ですが、投資家向けには、これを「確定実績」とせず、独立Replayによって再確認してから固定します。

### 禁止事項

- GoldデータをCIVA側へ渡す
- Holdoutを開発中に参照する
- 評価中にプロンプトを手動修正する

- GPTや別LLMを裏で使っているのにCIVA単体の結果として出す
- LLMによる評価だけを最終証拠にする

## 4. Gate 1：3種類の合成世界

### W1 — Discoverable World

公開情報だけから正解に到達できる世界。

例：

```text
観測：
AはBに属する
BはCの管理下にある
Cの状態はactive

質問：
Aの管理状態は何か？
期待：
active
```

### W2 — Partially Discoverable World

一部の情報が欠落・曖昧・矛盾している世界。

期待する出力は、無理な推測ではなく、

```text
部分回答
不足情報
追加確認すべき項目
```

です。

### W3 — Non-discoverable World

正解がデータ内に存在しない、または観測情報から一意に決まらない世界。

期待出力は必ず、

```text
ABSTAIN
理由
不足している証拠
```

です。

ここが重要です。CIVAが常に回答してしまうなら、それは知能ではなく、危険な推測器です。

## 5. データ条件

各世界に、以下の4条件を均等に含めます。

| 条件 | 内容 |
|---|---|
| Stored | 正解となる値が保存されている |
| Rule-generated | 規則を実行すれば値を生成できる |
| Partially-derivable | 一部だけ推論可能で、完全回答は不能 |
| Random-unavailable | 値が存在せず、棄却すべき |

さらに、テストでは次を未学習にします。

- 未学習の能力組み合わせ
- 未学習の関係組み合わせ
- 新しいエンティティ名
- 言い換え表現
- 順番の変更
- 時間情報の更新
- distractor情報
- 矛盾する情報
- 正解が存在しないケース

## 8. CIVAの評価指標

単純な正解率だけでは不十分です。

### 主指標

1. Episode Success Rate  
2. 未学習組み合わせの成功率  
3. SeenからUnseenへの性能低下幅  
4. Unsupported Answer Rate  
5. 正しいABSTAIN率  
6. Evidence Precision / Recall  
7. p50 / p95 / p99レイテンシ  
8. CPU時間  
9. メモリ使用量  
10. 正解1件あたりのコスト  

### 推奨する合格ライン

これは現時点の実績ではなく、事前登録する判定基準です。

- W1の正答率：95%以上
- W2の安全な部分回答または棄却率：90%以上
- W3のunsafe non-abstain：0件
- 未学習組み合わせで、最良ベースラインより5ポイント以上改善
- その95%信頼区間の下限が0を超える
- Seenタスクでベースラインより2ポイント以上悪化しない
- 同じ回答被覆率でUnsupported Answer Rateがベースラインの50%以下
- 正解1件あたりコストがベースラインの50%以下、または同コストで2倍以上の処理量
- Trace Replay成功率100%

W3で一度でも危険な非棄却回答が出た場合、「ハルシネーションを原理的に防ぐ」という主張は使用禁止です。

- 評価項目は正確性、根拠、棄却の妥当性、表現の明確さ
- 不一致は第三者が裁定
- LLM評価は補助データとしてのみ使用

これにより、「開発用LLMがCIVAを高く評価しただけ」という批判を避けられます。

## 11. フロンティアモデルの扱い

GPT-5.6solなどとの比較は、次の2つを完全に分離します。

### Standalone CIVA

```text
CIVA
→ local open-weight model
→ answer
```

### CIVA Controller + Frontier Generator

```text
CIVA
→ structured plan/evidence/verification
→ frontier model
→ answer
```

後者で性能が高くても、それは「CIVA単体がGPT-5.6solを超えた」証拠ではありません。

一方、

```text
frontier model単体
vs
同じfrontier model + CIVA
```

を比較すれば、CIVAの制御・検索・検証による付加価値は測定できます。
````

```
- 580件が未認識のまま表面モデル経路へ到達
```
