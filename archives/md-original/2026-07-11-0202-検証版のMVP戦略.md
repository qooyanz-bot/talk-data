````
「**検証版**」は、EnterpriseOSの最初のMVPで**自社開発を最小限に抑え、本当に市場にニーズがあるかを検証するフェーズ**です。

ここで重要なのは、「AIサイトビルダーを作ること」ではなく、「EnterpriseOSのビジネスモデルが成立するか」を検証することです。

---

# なぜ検証版が必要なのか

EnterpriseOSは本来、

- AIサイト生成
- CMS
- ビジュアルエディタ
- ホスティング
- SSL
- ドメイン
- DNS
- CDN

まで全部作ることもできます。

しかし、それを最初から作ると、

**完成まで半年〜1年以上**かかる可能性があります。

その間、

「そもそも企業は買うのか？」

が分かりません。

これはスタートアップでは避けるべきです。

---

# 検証版で自社が作るもの

EnterpriseOSが作るべきなのは、

```
会社情報DB
↓

会社情報解析AI

↓

会社WEB自動生成プロンプト

↓

代理店管理

↓

契約

↓

決済

↓

ドメイン

↓

公開
```

つまり

**EnterpriseOS独自の価値**

だけです。

---

# 作らないもの

例えば

```
ページドラッグ編集

画像配置

レスポンシブレイアウト

CMS

HTML生成

CSS生成

公開サーバー
```

これはBrizyに任せます。

つまり

```
EnterpriseOS
↓

Brizy
```

です。

---

# 検証版の流れ

例えば新設法人が見つかったとします。

```
EnterpriseOS

↓

会社情報取得

↓

AI解析

↓

会社概要生成

↓

事業紹介生成

↓

採用ページ生成

↓

問い合わせ生成

↓

Brizyへ投入
```

すると

Brizy側で

```
完成済みサイト

↓

プレビュー

↓

URL発行
```

になります。

EnterpriseOSは

完成したURLを取得します。

---

# パートナーは何をする？

ここがかなり重要です。

EnterpriseOSでは

パートナーは

**ゼロから作りません。**

例えば

```
AI完成度

85%
```

くらいまで出来ています。

パートナーは

```
文章修正

画像変更

ロゴ追加

色変更

CTA修正

問い合わせ確認
```

だけ。

だから

作業時間が

```
20時間

↓

3時間
```

になります。

これが利益になります。

企業から見ると

突然

```

```

というメールが届きます。

開くと

```
https://preview.enterpriseos.jp/xxxxx
```

会社サイトが出来ています。

しかも

```

会社概要

ニュース

問い合わせ

プレスリリース

会社紹介
```

全部あります。

企業は

「これなら欲しい」

となります。

# この段階ではAPIは使わない

ここが検証版のポイントです。

最初は

EnterpriseOSが

```
JSON生成
```

↓

パートナーが

```
Brizyへコピー
```

でも構いません。

つまり

半自動です。

例えば

```
会社情報

↓

AI

↓

JSON
```

```json
{
  "company":"株式会社ABC",
  "hero":"AIで物流を変える",
  "about":"・・・",
  "services":[...]
}
```

これを

Brizyへ貼るだけ。

これでも十分検証できます。

API開発は

かなり工数があります。

例えば

```
企業100社

↓

自動生成

↓

API送信

↓

↓

↓

しかし

重要なのは

```

ではなく

売れるか
```

です。

# 5〜10社売れたらAPI版へ移行

このタイミングで

```
EnterpriseOS

↓

REST API

↓

Brizy API

↓

サイト生成
```

になります。

すると

企業情報を取得した瞬間

```

サイト完成
```

になります。

---

# 私ならさらに設計を変える

EnterpriseOSの将来を考えるなら、**最初からBrizyを直接呼び出さず、抽象レイヤーを1枚入れる**ことを強く勧めます。

```
EnterpriseOS

↓

SiteBuilderProvider
      │
 ├── Brizy
 ├── 10Web
 ├── Site.pro
 └── 将来自社Builder
```

これにすると

将来

```
Brizy

↓

10Web
```

へ変更しても

EnterpriseOS本体はほぼ変更不要です。

さらに数年後、

自社製Web Builderが完成したら

```
EnterpriseOS

↓

Enterprise Builder
```

へ置き換えられます。

---

## EnterpriseOSにとって本当に重要な資産

ここが一番重要です。

EnterpriseOSの価値は**Webサイトを生成することではありません**。

価値があるのは次の資産です。

- 約500万社の企業データベース
- 企業情報の構造化エンジン
- AIによる会社情報・採用・ニュース・IRページ生成
- 企業確認（Claim）フロー
- Openproviderによるドメイン取得・管理
- パートナーマーケットプレイス
- 契約・請求・運用管理
- 営業シグナルとの連携

Webサイト生成エンジンは、現時点では交換可能な部品として扱うのが最もリスクが低く、開発速度も上げられます。これが検証版アーキテクチャを採用する最大の理由です。
````
