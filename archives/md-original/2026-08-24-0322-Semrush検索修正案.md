## HTMLを保存すると4パターンに切り分けられます

一番可能性が高いのは、**結果画面には到達しているがExportボタンのセレクタだけ古い**ケースです。この場合は簡単で、保存HTMLから新しい属性を見つけてPlaywrightを修正すれば終わります。

次にあり得るのが、検索語を入力しているものの、Keyword Magic Toolではなく別ページに着いているケースです。この場合はURLや遷移ロジックを直します。

3つ目は、

```text
Upgrade
Trial expired
Limit reached
```

などが出ているケースです。これはUIの問題ではなくSemrush側の契約・利用上限の問題です。

4つ目が認証です。

```text
Sign in
Log in
session expired
```

などがHTML内にあれば、保存した`.semrush_session`が有効でなくなっています。この場合は再度、

```powershell
python pilot/semrush_export_parallel.py --login
```

を実行すればいい、という切り分けになります。

## なぜスクリーンショットではなくHTMLなのか

画面を見れば「Exportボタンあるじゃん」と分かりますが、Playwrightには**DOM上でどう識別すればいいか**を教える必要があります。

例えば人間には、

> Export

と見えていても、Playwrightから見ると、

```html
<button
  data-test="keyword-magic-export"
  aria-haspopup="menu"
>
   <span>Export</span>
</button>
```

かもしれません。

この場合、

```python
page.locator('[data-test="keyword-magic-export"]')
```

と指定すれば非常に安定します。

逆に、

```python
page.get_by_text("Export")
```

だと、

- Exportという文字が複数存在
- 日本語UIでは「エクスポート」
- spanが動的レンダリングされる
- ボタン自体がiframe内

などで失敗することがあります。

したがって今回は、**HTML→正しいDOM属性→安定したPlaywrightセレクタ**という順で直そうとしています。
