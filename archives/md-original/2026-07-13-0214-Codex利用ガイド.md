このページは、**ChatGPTの契約プランでCodexをどう利用できるか**をまとめた公式ガイドです。2026年7月11日ごろ更新された新しい内容で、従来よりCodexの対象範囲が広がっています。

## 結論

Codexは現在、Free・Goを含むChatGPTの各プランに含まれています。ただし、プランごとに利用量・追加クレジット・管理機能が異なります。

利用できる主な場所は次の5つです。

- ChatGPTデスクトップアプリのCodexモード
- Codex CLI
- VS CodeなどのIDE拡張
- Codex Web
- クラウド上で実行するCodexタスク

APIキーを別途購入しなくても、ChatGPTアカウントでサインインして使えます。

## 重要な変更点：利用枠が共通化されている

特に重要なのは、次の機能が**同じ「エージェント利用枠・クレジットプール」から消費される**という点です。

- Codex
- ChatGPT Work
- ChatGPT for Excel
- Workspace Agents

つまり、ChatGPT Workを大量に使った場合、Codexで使える残量にも影響する可能性があります。

消費量は単純なメッセージ数では決まりません。

- 対象コードベースの大きさ
- タスクの複雑さ
- 使用モデル
- ローカル実行かクラウド実行か
- 作業時間やセッションの長さ

によって変動します。小さな修正は消費が少なく、大規模リポジトリの調査や長時間の自律実装は大きく消費します。

## 上限に達したらどうなるか

作業中に上限へ到達しても、原則として**そのターンは完了まで継続可能**です。ただし、公正利用上の制限はあります。

その後はプランに応じて、以下の選択肢が表示されます。

- クレジットを追加購入する
- 紹介特典などで得たリセットを使う
- 上位プランへ変更する
- 利用枠がリセットされるまで待つ

残量はCodexのUsageページまたは上限通知バナーで確認します。

## ChatGPTの他の上限とは別物

以下の制限はCodexの利用枠とは別です。

- ファイルアップロード制限
- 画像生成回数
- 音声モード上限
- 動画生成上限

そのため、ChatGPTで「画像生成はあと○回」などと表示されても、Codexのコード作業枠には直接関係しません。

## データが学習に使われるか

契約形態によって違います。

| プラン | 標準設定 |
|---|---|
| Plus・Proなど個人向け | 会話がモデル改善に使われる可能性あり |
| Business | 標準では学習に使用されない |
| Enterprise・Edu | 標準では学習に使用されない |
| API | 標準では学習に使用されない |

個人プランでは、ChatGPTの「設定 → データコントロール」からモデル改善への利用をオフにできます。Codexで処理した内容やComputer Useのスクリーンショットにも、この設定が適用されます。

企業の未公開コードを扱うなら、個人プランのまま無頓着に使うのは避けるべきです。少なくとも学習設定をオフにし、本格的な組織利用ならBusiness以上を検討するのが妥当です。

## プラグインについて

プラグインディレクトリ自体は各プランから見えますが、実際にインストール・使用できるかは以下で決まります。

- ChatGPTプラン
- ワークスペース設定
- ユーザーのロール
- 使用している画面・クライアント
- 接続アプリの権限
- 管理者の許可

Business・Enterprise・Eduでは、管理者が「Workspace settings → Plugins / Apps」から制御します。

プラグインには以下をまとめて含められます。

- Skills
- 外部アプリ接続
- アプリテンプレート
- Codex固有のツールやワークフロー

## AGENTS.mdを簡単に作れる

CodexモードまたはCLIで次を実行できます。

```text
/init
```

これにより、現在のプロジェクト用の`AGENTS.md`ひな型が生成されます。

`AGENTS.md`には例えば以下を記載します。

- プロジェクトの目的
- 採用技術
- 実行・テストコマンド
- コーディング規約
- 触ってはいけない領域
- 完了条件
- レビュー基準

EnterpriseOSやBrandForgeのような長期開発では、会話だけに仕様を持たせるより、リポジトリ内の`AGENTS.md`へ永続的な開発ルールを書く方が確実です。

## のりあきさんに関係する実務的なポイント

最大の注意点は、**ChatGPT WorkとCodexを無制限の別枠だと考えないこと**です。同じ利用枠を共有するため、長い事業計画をWorkで作りながら、Codexで大規模実装を続けると消費が集中します。

おすすめの使い分けは次です。

- ChatGPT Work：事業計画、調査、仕様書、比較資料
- Codex：リポジトリ調査、実装、テスト、コミット前の検証
- `AGENTS.md`：確定した製品方針や開発ルール
- `docs/`：詳細仕様、データモデル、ロードマップ
- GitHub Issues：未実装タスクと優先順位

もう一つ重要なのは、**ChatGPTの会話履歴が自動的に全部Codexへ移るわけではない**ことです。過去の重要な決定は、`AGENTS.md`や仕様書としてリポジトリへ明文化する必要があります。
