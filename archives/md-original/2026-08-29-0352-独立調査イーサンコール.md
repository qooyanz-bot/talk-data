## 2. 3種類のResolver

| Resolver | 役割 | 適用条件 | 失敗時 |
|---|---|---|---|
| `RuleResolver` | 決定的ルール・関係計算 | Addressが完全で、該当ルールが存在 | MemoryへFallback |
| `MemoryResolver` | Synthetic Knowledge Graph / Index参照 | Addressは正しいが、ルール計算だけでは不足 | Small ModelまたはABSTAIN |
| `SmallModelResolver` | 曖昧な自然言語や未学習のslot組合せを局所変換 | 必要証拠が存在し、候補生成が許可される | NOT_DERIVABLEまたはABSTAIN |

重要な制約：

- Small ModelはGold、target value、将来情報を受け取らない。
- Resolverは「答えを推測する」のではなく、Typed Addressに対して自分が実行可能かを判定する。
- `NOT_DERIVABLE`を返すべきケースで、別Resolverを無限に試さない。

## 5. E2Eコスト測定表

実測値はまだ投入せず、以下の形式で固定します。

| 項目 | Direct-call | 固定順序Router | Address-routed Router |
|---|---:|---:|---:|
| Dispatch API call | 0または1 | 1 | 1 |
| Registry lookup | 0 | 0 | 1 |
| Resolver call | 1 | 最大3 | 通常1 |
| Retry | Resolver依存 | 各Resolver依存 | 選択Resolverのみ |
| Routing CPU | 0 | 測定 | 測定 |
| Resolver CPU | 測定 | 合計 | 測定 |
| Verification CPU | 共通 | 共通 | 共通 |
| Request payload | 測定 | 測定 | 測定 |
| Response payload | 測定 | 測定 | 測定 |
| Verification count | 1 | Resolverごと | 選択Resolver＋最終検証 |
| E2E latency | 測定 | 測定 | 測定 |
| Abstention correctness | 測定 | 測定 | 測定 |

計算式：

```text
E2E_CPU
= routing_cpu
+ Σ(resolver_cpu × attempts)
+ retry_cpu
+ verification_cpu

E2E_payload
= dispatch_request
+ Σ(resolver_request + resolver_response)
+ dispatch_response

E2E_API_calls
= registry_calls
+ resolver_calls
+ retry_calls
```

期待される構造上の差は以下です。

```text
Address-routed Router
  → 候補選択後に不要なResolverを呼ばない
  → 固定順序RouterよりResolver call数が減る可能性

Direct-call
  → 最速の下限
  → ルーティング判断のコストを含まないため、性能優位の証明には使えない
```

最低限の判定条件：

- 同一のRESOLVED率・NOT_DERIVABLE判定を維持する
- Address-routedが固定順序RouterよりResolver call数を削減する
- timeout時にretry上限を超えない

- NOT_DERIVABLEで推測値を返さない
- unseen compositionでtarget IDの暗記を使わない
- 外部LLM・BYOK・秘密情報に一度もアクセスしない

## 7. 反証条件とFAIL

以下のいずれかが起きた場合、RACR仮説はその実験条件で`FAIL`とします。

- Address-routed Routerが固定順序Routerより常に高コスト
- Capability選択理由が実行後にしか生成できない
- required evidenceなしでResolverが実行される
- `NOT_DERIVABLE`をSmall Modelの推測で埋める
- timeout後の無制限retry、または非冪等処理のretry
- unseen compositionでtarget valueを直接参照する
- registryにないCapabilityが実行される
- 検証処理を省略すると正解扱いになる
- 外部LLMへの実通信が発生する
