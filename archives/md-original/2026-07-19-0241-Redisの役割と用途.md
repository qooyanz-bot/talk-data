## Redisとは

entity["other","Redis","インメモリデータストア"] は、データをメモリ（RAM）上に保持する超高速なデータベースです。

通常のデータベース（PostgreSQLなど）はディスクへ保存しますが、

- PostgreSQL：永続保存（遅いが安全）
- Redis：メモリ保存（非常に高速）

という役割分担になります。

例えば、

```
ユーザー
    ↓
Webアプリ
    ↓
Redis ← 0.5ms
    ↓
PostgreSQL ← 数ms〜数十ms
```

のようになります。

つまり、

```
Coolify
   ↓
Redis
```

という関係です。

# Queue

Redisは

```
順番待ち
```

にも使います。

例えば

```
企業100万社更新
```

すると

```
Agent

↓

Redis Queue

↓

Worker1

Worker2

Worker3

...
```

という構成になります。

Cloudflare Queuesを使う方法もありますが、Redisベースのキュー（例: BullMQ）もNode.jsでは非常に一般的です。

# DealVaneでのおすすめ構成

あなたの構想（500万社DB、AIエージェント、企業ページ自動生成）なら、次の役割分担が適しています。

| 用途 | サービス |
|------|----------|
| 永続データ（企業情報・ユーザー情報） | PostgreSQL |
| キャッシュ | Redis |
| AI応答キャッシュ | Redis |
| セッション管理 | Redis |
| ジョブキュー | Redis（またはCloudflare Queues） |
| ベクトル検索 | PostgreSQL + pgvector |
| 全文検索 | PostgreSQL（必要に応じて専用検索エンジンを追加） |
| オブジェクト保存 | Cloudflare R2 |

## あなたの構想ではRedisは必須か？

500万社規模の企業DBとAIエージェントを前提にすると、**はい、実質的に必須**です。ただし重要なのは、**現在Coolifyに入っている`coolify-redis`をそのままアプリで共用しないこと**です。

そのRedisはCoolify自身の運用に使われています。DealVane用には、Coolify上で**別のRedisサービス**を作成し、アプリ専用として使うことをおすすめします。そうすると、アプリの負荷や設定変更がCoolify本体へ影響することを避けられ、バックアップやスケーリングも独立して管理できます。
