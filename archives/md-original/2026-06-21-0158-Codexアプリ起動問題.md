````
まず **設定ファイルを一時退避して起動できるか** を確認してください。  
あなたの環境では、Codex CLI に `sakura_ai_engine` を設定しているため、ここが最有力です。CodexアプリはCLI／IDE Extensionの設定を共有します。citeturn593907view1turn629965view0

PowerShell を開いて、順に実行します。

```powershell
taskkill /F /IM Codex.exe
```

```powershell
Rename-Item "$HOME\.codex\config.toml" "config.toml.bak-20260621"
```

その後、Codex Windowsアプリを起動してください。

### 起動した場合
原因は `config.toml` 側です。削除ではなく退避しているだけなので、設定は残っています。

アプリ用は標準のOpenAI設定にして、さくらのAI Engine用は**プロファイルに分離**するのが安全です。

```powershell
Rename-Item "$HOME\.codex\config.toml.bak-20260621" "sakura.config.toml"
```

以後、さくらのAI EngineをCLIで使うときだけ：

```powershell
codex --profile sakura
```

Codexは `~/.codex/<profile名>.config.toml` のプロファイル設定をサポートしています。グローバル設定に外部providerを常駐させると、アプリ側まで影響します。citeturn629965view0

### まだ起動しない場合
Windowsのアプリ修復を実行します。

1. **設定** → **アプリ** → **インストールされているアプリ**
2. `Codex` → `…` → **詳細オプション**
3. まず **修復**
4. 起動しなければ **リセット**
   - ログイン状態やローカルUI設定は消えますが、`%USERPROFILE%\.codex` の設定・セッションを消す操作ではありません。

それでも駄目なら、Microsoft Storeから一度アンインストールして再インストールしてください。Store版は 2026年6月20日に更新されています。citeturn723836search28

### それでも即終了する場合
クラッシュ記録を確認します。

```powershell
Get-WinEvent -FilterHashtable @{
  LogName='Application'
  StartTime=(Get-Date).AddHours(-2)
} |
Where-Object { $_.Message -match 'Codex|OpenAI' } |
Select-Object TimeCreated, ProviderName, Id, LevelDisplayName, Message |
Format-List
```

表示された `Message` 全文、または「起動時に一瞬だけ出て消える／何も出ない／白画面になる」のどれかを送ってください。  
なお、現時点のOpenAIステータスでは一般的なCodex障害は出ておらず、FedRAMP環境の劣化のみが掲載されています。citeturn638462view0
````
