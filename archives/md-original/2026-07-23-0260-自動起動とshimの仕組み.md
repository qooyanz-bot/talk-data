ここでいう**「自動」**とは、**OpenCodex（ocx）がCodexの前段に入り、毎回手動で `ocx start` を実行しなくても、自動的にプロキシが起動する仕組み**のことです。

仕組みを図にするとこうなります。

```text
通常

あなた
   │
   ▼
codex.exe
   │
   ▼
OpenAI API
```

これを OpenCodex を使うと、

```text
あなた
   │
   ▼
codex   ← 実際には shim
   │
   ▼
OpenCodex (ocx)
   │
   ├── 起動していなければ自動起動
   │
   ▼
OpenAI API
```

になります。

---

## shimとは？

shimは**代理人**です。

例えばWindowsで

```
codex
```

と入力した時、

普通なら

```
codex.exe
```

が起動します。

しかし shim を入れると、

```
codex
```

↓

```
codex.cmd
```

↓

```
OpenCodexが起動している？
```

↓

起動していなければ

```
ocx start
```

↓

そのあと

```
本物の codex.exe
```

を起動します。

つまり

**ユーザーは何も意識しなくていい**

というのがshimの目的です。

---

## なぜcodex.exeでは失敗したのか

WindowsではPATHに

```
codex.exe
```

があると

Windowsは

```
codex.cmd
```

より

```
codex.exe
```

を優先します。

つまり

```
codex
```

↓

直接

```
codex.exe
```

になってしまいます。

すると

```
OpenCodex
```

を経由できません。

だから

```
ocx codex-shim install
```

は

> codex.exe があるので安全のため変更しません

と拒否しました。

---

## なぜ自前の `.cmd` を置くの？

PATHの先頭に

```
C:\Users\あなた\.local\bin
```

を置くと

Windowsは

```
.local\bin\codex.cmd
```

を先に見つけます。

つまり

```
codex
```

↓

```
codex.cmd
```

↓

```
OpenCodex
```

↓

```
本物のcodex.exe
```

という順番になります。

これが

> PATHの先頭にラッパーを置く

という意味です。

---

## `ocx service install` との違い

こちらはshimとは考え方が違います。

サービスとして

```
Windows起動
```

↓

```
OpenCodex常駐
```

になります。

つまり

```
PC起動
```

↓

```
OpenCodex
```

↓

```
codex.exe
```

という構成です。

そのため

```
codex.exe
```

を置き換える必要がありません。

---

## あなたの環境ではどちらがおすすめ？

現在の環境は

- OpenAI公式Codexを利用
- Windows版Codex
- `codex.exe` がインストール済み
- OpenCodexを追加

という構成なので、

### ① `ocx service install`（おすすめ）

メリット
- `codex.exe` を変更しない
- OpenAI公式の更新で壊れにくい
- 一度設定すればPC起動時に自動で利用できる

デメリット
- OpenCodexが常駐する

---

### ② shim方式

メリット
- 必要なときだけOpenCodexが起動
- メモリ消費を抑えられる

デメリット
- PATHの優先順位を理解して設定する必要がある
- Windows環境では少し設定が複雑

---

あなたのように**EnterpriseOSを日常的にCodexで開発する用途**であれば、私は**`ocx service install` の構成を優先**します。公式の `codex.exe` をそのまま利用でき、WindowsアップデートやCodex更新の影響も受けにくく、日常運用がシンプルだからです。一方、リソース消費を最小限にしたい場合はshim方式が適しています。
