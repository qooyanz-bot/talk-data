# 開発実装のみフロンティア級 提案 v0
# Dev-Frontier（DF-1）

日付: 2026-09-05
関係: GSMのU2特化 / SMQ・CSR-1の縮小版

## 1. 答え
**可能（提案として強い）。**  
全用途ChatGPT置換（CSR-1の最大目標）より、**開発実装ドメイン限定のフロンティア級**の方が単一GPU・寄せ・量子化と整合する。

## 2. 成功定義（限定）
「フロンティア級」を次に限定する:
- コード生成・修正・テスト案・デバッグ手順・PR説明・簡易設計
- 参照: 最新の強コードモデルAPI（例: フロンティアのコード能力）との **実用置換率**
- やらない: 創作小説、医療、広い雑談でChatGPTに勝つ

合格例:
- HumanEval / 内部リポジトリ課題 / U2テストで目標帯
- 制限テスト（攻撃コード等）≥90%拒否
- 単一GPUで実用レイテンシ

## 3. アーキテクチャ DF-1

```
要求（issue/差分/エラーログ）
  → ゲート0（攻撃・破壊・秘密）
  → 寄せ: 常に「開発実装」プロファイル（分類はサブタスクのみ）
  → 単一GPU核
       幹: RMSNorm + SwiGLU（コード向け微調整可）
       MoE/LoRA: 実装 / テスト / デバッグ / レビュー のexperts
       QPS: INT4〜FP8（コードはビット厚め寄り）
       MTP or 小ドラフタ: 補完速度
  → 道具: リポジトリRAG、テスト実行、linter、型チェック
  → ゲート1: テスト失敗・危険コマンドの止め
  → R2（パッチ・手順・説明）
```

ポイント: **道具＋テスト実行**が「級」の本体。純補完だけではフロンティアに届きにくい。

## 4. なぜ全部置換より現実的か
| | 全置換 CSR-1 | 開発のみ DF-1 |
|---|---|---|
| ドメイン幅 | 広い | 狭い（寄せやすい） |
| 検証 | 曖昧 | テスト実行で客観的 |
| VRAM | 多experts必要 | experts少数で足りる |
| 単一GPU | 厳しい | **本命** |

## 5. ハードウェア
| GPU | DF-1机上 |
|---|---|
| **24–48GB** | 小〜中コードモデル＋道具で十分始められる |
| **80–96GB** | より強いコードMoE/長コンテキスト |
| 水200単枚 | 余裕（必須ではない） |

全置換より **安いGPUで検証開始可能**。

## 6. 最小検証プラン
1. 単一GPUにコード向けオープンモデル（量子化）
2. リポジトリRAG＋テスト実行ツール
3. U2の10問＋自前の小さなバグ修正5題
4. フロンティアコードAPIと盲検比較
5. 置換率・テスト通過率を記録

## 7. 一文
**開発実装のみに寄せた幹＋少数experts＋量子化＋MTP/ドラフタ＋テスト実行道具なら、単一GPUでフロンティア級（コード領域）の提案・検証は可能。**
