## 0. 検証対象スタック（K指定）

ある程度寄せた前提で、次を同時に持つモデル:

| 部品 | 役割 |
|---|---|
| **RMSNorm** | 安定な正規化（現代LLMの標準幹） |
| **SwiGLU** | FFNの活性化（表現力・標準幹） |
| **MTP and/or drafter** | 複数トークン案 → 検証で高速化（省力＝時間） |
| **MoE** | 活性パラメータだけ動かす（省力＝FLOPs/電力） |
| **QPS/省力化・量子化** | ビット幅・未使用expertsの抑制（省力＝VRAM） |
| **ある程度寄せ** | GSM/SMQ: ドメインへSteer＋ゲート |

これを **SMQ-Full Stack** と呼ぶ（作業名）。

## 1. 検証結論（机上）

| 問い | 判定 |
|---|---|
| この部品セットは互いに矛盾するか | **ほぼ矛盾しない**（現代オープン最上位の常套組み合わせ） |
| 単一GPUで **F★（ChatGPTそのもの）** | **不可寄り**（品質・生態・総容量） |
| 単一GPUで **F1-S（ドメイン束の準フロンティア）** | **条件付き可能**（96GB級＋量子化＋活性MoE＋MTP/ドラフタ） |
| 「寄せ」が単一GPUに効くか | **効く**（起こすexpertsとビットを減らせる） |

**総合**: 検証仮説として採用してよい。  
「単一GPUフロンティア級」は **F1-SとしてYes机上 / F★としてNo**。

## 2. 各部品の寄与（検証メモ）

### RMSNorm + SwiGLU
- 品質の「土台」。単一GPU可否を直接は決めない。
- 寄せとは独立。実装コストは低い（標準）。
- **判定**: 必須の幹。省力の主役ではないが外さない。

### MoE（ある程度寄せた）
- 総パラ大きくても **活性は小さい** → 単一GPUの計算側に有利。
- ただし **全expertsの重みをVRAMに常駐**させると単一GPUが破綻。
- **寄せ**: ドメイン優先ルーティングで、載せる／起こすexpertsを減らす → 単一GPU必須条件。
- **判定**: F1-Sの主エンジン。寄せなしMoEは単一GPUで詰みやすい。

### QPS（量子化・省力）
- INT4/FP8でVRAMを削る。Pro 6000 96GB / H100 80GB の単一運用の鍵。
- 品質下限をテストで監視（制限テストが崩れないこと）。
- **判定**: 単一GPUの主制約解除装置。

### MTP and/or drafter
- **時間の省力**（tok/s向上）。VRAMはMTP内蔵なら追加小、外付けドラフタは小モデル分増。
- 文献・実装例: MTPでおおよそ **1.2〜2×** 程度の速度向上が報告されることあり（設定依存）。
- 品質は「検証ステップ」があるため、ドラフト誤りは本モデルが落とす設計。
- **判定**: 単一GPUの体感フロンティア（速さ）に効く。品質F1の必要条件ではないが、実用には強い。

### ある程度寄せ（GSM/SMQ）
- 分類→ドメインexperts → ゲート。
- 「全部のChatGPT能力を1枚に」ではなく「今の用途に寄せた切片」。
- **判定**: 単一GPUでF1-Sを主張するための **成功定義そのもの**。

## 4. 参照実装パス（検証のやり方）

### Phase A — 部品単体スモーク（1枚）
1. RMSNorm+SwiGLUの既存チェックポイントを1つ固定（例: オープンMoE小〜中）
2. 量子化ロード成功
3. MoE routerが動く
4. MTP **または** 外付けdrafterのどちらか一方をオン（同時は衝突しうるので最初は片方）
5. 短文生成・tok/s記録

### Phase B — 寄せを足す
1. 分類機（U1–U6）
2. ドメインLoRA/expertsを2つだけ（U1,U2）
3. ゲート（制限10問）

### Phase C — F1-S判定
1. テストバンク U1/U2（各S5+R5）
2. 参照フロンティアAPIと要点一致
3. 制限率が崩れない
4. 目標tok/s（例: 対話20+）を単一GPUで満たすか

### 合格ライン（提案）
- 寄せ成功率 ≥ 0.7
- 制限成功率 ≥ 0.9
- 要点一致が「実用」帯（人手 or ルーブリック）
- 単一GPU・設定を文書化

不合格でも「どの部品がボトルネックか」を記録すれば検証成功。

## 5. MTP vs 外付けドラフタ（選び方）

| | MTP内蔵 | 外付けdrafter |
|---|---|---|
| 追加VRAM | 小さいことが多い | ドラフトモデル分 |
| 運用 | チェックポイント一体 | 二体管理 |
| 寄せとの相性 | 幹に寄せexperts | ドラフトもドメイン別可 |
| 初期検証 | **どちらか一方** | 両方同時は後回し |

机上おすすめ: まず **MTP**（あるなら）→ だめなら小drafter。

## 6. リスク（検証で見るべき失敗）
- MoE全experts常駐でOOM
- 量子化でコード域（U2）だけ品質崩壊
- MTP受容率が低く逆に遅くなる
- 分類ミスで危険域
- 「部品が揃った＝F★」と誤記

## 7. 一文の検証回答
**RMSNorm・SwiGLUを幹に、ある程度寄せたMoEと量子化省力でVRAM/活性を抑え、MTPまたはドラフタで時間を省力する構成は、単一GPUにおける準フロンティア（F1-S）検証に適合する。ChatGPTそのもの（F★）の単一GPU達成検証には不適合。**
